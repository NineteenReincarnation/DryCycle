============================================================
0. 背景与已确认事实
============================================================

0.1 当前 DryCycle Observatory 已经证明 ImGui Core 本身可以运行

用户实机日志已经确认：

- F7 可被 Unity Input 正确检测。
- cimgui native preload 成功。
- ImGui Context 成功创建。
- Font Atlas 成功创建。
- DockingEnable 在首个 NewFrame 前成功配置。
- Window.Draw 成功执行。
- ImGui.Render 成功生成 DrawData。
- DrawData.CmdListsCount > 0。
- DrawData.TotalVtxCount > 0。
- DrawData.TotalIdxCount > 0。
- Unity Mesh 成功构建。
- CommandBuffer 中存在有效 DrawMesh 命令。
- Overlay Camera OnPostRender 成功触发。

因此当前主要问题已经不是“ImGui 没生成 UI”，而是 DryCycle 自己承担了过多 Renderer Backend / Presentation Backend 职责。

0.2 当前自研 Renderer 的问题

当前链路大致为：

ImGui.NET
  -> ImDrawData
  -> DryCycle BuildMesh
  -> Unity Mesh
  -> Unity Material
  -> Unity CommandBuffer
  -> Dedicated Camera
  -> Futile RenderTexture / Backbuffer
  -> Rain World presentation

该路径需要 DryCycle 自己处理：

- ImGui context 生命周期
- native cimgui 加载
- font atlas
- vertex/index 转换
- VtxOffset / IdxOffset
- texture id
- scissor
- Y flip
- framebuffer scale
- projection matrix
- shader
- camera
- command buffer
- render target
- Futile presentation
- fullscreen / resize / render texture recreation

这些工作已经超出 AI Observatory 本身职责，而且与 Rain World 最终 DX11 presentation 管线高度耦合。

0.3 RWImGUI 的已确认能力

Rawra 官方 README 明确说明：

- 面向 Rain World 的 Dear ImGui API。
- Windows x64 / Rain World 1.10+ 使用 Latest。
- Renderer/Platform backend 基于 Win32 + DX11。
- 接入 Rain World 的 IDXGISwapChain::Present。
- 其他 Mod 可以注册绘制 callback。
- 也提供自己的 Context 机制以获得更多控制。
- 使用经过修改的 ImGui.NET bindings，而不是要求依赖普通 NuGet ImGui.NET。
- 官方项目包含 Example Project。

截至本任务书编写时，公开 tag 中可见 v1.10.10（2026-02-20），且项目在 2026-08 仍有活动。

0.4 最终技术决策

AI Observatory 不再自行实现 DX11/Unity ImGui Renderer Backend。

正式目标架构：

Rain World Main Thread
  -> AI Observatory Controller / Capture / Trace / Commands
  -> immutable Presentation Snapshot
  -> RWImGUI callback/context
  -> ImGui UI
  -> RWImGUI Win32 + DX11 backend
  -> IDXGISwapChain::Present

DryCycle 只负责：

1. AI 数据采集。
2. 调试状态管理。
3. UI 要显示的数据模型。
4. UI 发回主线程的命令。
5. Observatory 自己的 ImGui widget 内容。

RWImGUI 负责：

1. ImGui native/backend 生命周期。
2. Win32 input backend。
3. DX11 renderer backend。
4. SwapChain Present hook。
5. ImGui frame 的底层提交。
6. native binding 的正确版本组合。

============================================================
3. 强制架构原则
============================================================

3.1 Rain World / Unity 对象只在主线程读写

RWImGUI 的绘制 callback 必须按“可能处于 render/present 线程”处理。

除非该版本官方文档明确保证 callback 运行于 Unity 主线程，否则 callback 中禁止直接访问：

- RainWorld
- RainWorldGame
- Room
- RoomCamera
- AbstractCreature live object
- realized Creature
- ArtificialIntelligence
- UnityEngine.Input
- UnityEngine.Time
- UnityEngine.Object 生命周期 API
- AIDebugSimulationControl 对世界的实际推进函数

即使当前机器实测 callback 与主线程碰巧相同，也不得据此建立线程不安全架构。

3.2 UI 只能消费纯数据快照

RWImGUI callback 读取：

AIDebugPresentationSnapshot

不得在绘制函数里重新 Capture AI。
不得为了显示 Utility 再调用 AI module。
不得为了显示 Path 再读 live PathFinder。
不得为了 Why/Why Not 重新运行判断。

3.3 UI 操作通过 Command Queue 回主线程

所有会改变 Rain World / Observatory domain state 的操作：

- Select entity
- Compare entity
- Pin / Unpin
- Pause / Resume
- Step
- Clear Trace
- Export
- Reset world-facing overlay state
- world pick result

必须 enqueue，下一次主线程 Update 执行。

3.4 一个方向的数据流

主线程：
AI/RW -> Capture -> Presentation Snapshot -> atomic publish

UI callback：
Presentation Snapshot -> Draw UI -> enqueue commands

主线程：
Command Queue -> execute

禁止 callback 与主线程同时修改同一 List/Dictionary/StringBuilder。

============================================================
5. 依赖策略：禁止与 RWImGUI 的 ImGui.NET 冲突
============================================================

5.1 移除当前普通 NuGet ImGui.NET

当前：
src/Directory.Build.props

包含：

<PackageReference Include="ImGui.NET" Version="1.91.6.1" />

迁移后必须移除。

原因：

RWImGUI 使用自己的 modified ImGui.NET/native binding 组合。
DryCycle 不允许再把另一份同名/不兼容 ImGui.NET.dll 放到 plugins。

5.2 不再由 DryCycle 部署 cimgui.dll

当前自研 backend 所需的 cimgui native deployment 必须退出 DryCycle build output。

最终 plugins 目录中 RWImGUI 相关 native/runtime 文件必须由 RWImGUI Mod 自己提供。

DryCycle build 不得覆盖：

- RWImGUI assembly
- RWImGUI modified ImGui.NET
- RWImGUI native libraries

5.3 编译引用 Private=false

开发环境应新增：

RWImGuiDir
或
RWImGuiPluginDir

从用户本地已安装 RWImGUI Mod 的 plugins 路径引用实际 DLL。

所有 RWImGUI/modified ImGui.NET Reference：

<Private>false</Private>

不得复制进 Ancient Site/newest/plugins。

5.4 Build Validation

新增 MSBuild 验证：

- 如果构建 RWImGUI frontend project，则检查 RWImGUI API assembly 存在。
- 检查 modified ImGui.NET assembly 存在。
- 错误信息打印明确安装路径要求。

不要在 main DryCycle.csproj 的普通 C# 构建里强制要求 RWImGUI，见下一节的可选桥接程序集方案。

============================================================
9. Snapshot 发布机制
============================================================

最低实现：

- 主线程创建完整 snapshot。
- Volatile.Write(ref publishedSnapshot, snapshot)。
- RWImGUI callback 使用 Volatile.Read。

如果后续发现 allocation 明显：

再考虑双缓冲/对象池。

第一阶段禁止为了“零分配”引入复杂共享可变 buffer。
正确性优先。

采样频率建议：

- UI presentation snapshot：最多 10~20 Hz 更新 heavy sections。
- 基础 tick/paused 状态可每主线程 frame 更新 lightweight header。
- Trace 继续遵守现有 10 Hz sample 语义。

============================================================
11. RWImGUI Frontend 生命周期
============================================================

新增：
RWImGuiFrontend

职责：

1. 检测/确认 RWImGUI API ready。
2. 注册 callback。
3. 强引用 callback delegate，防止 GC。
4. 记录 API/version diagnostics。
5. 消费 published snapshot。
6. 调用 AIDebuggerImGuiView.Draw(snapshot)。
7. 更新 ImGui capture state cache。
8. 在卸载时注销 callback/context（如果 API 提供）。

强制规则：

如果使用 RWImGUI shared callback：

- 不调用 ImGui.CreateContext。
- 不调用 ImGui.DestroyContext。
- 不调用 ImGui.NewFrame。
- 不调用 ImGui.Render。
- 不调用自己的 DX11 draw submission。

如果使用 RWImGUI Context API：

- Context 必须由 RWImGUI API 创建/管理。
- 遵守其 Begin/End 生命周期。
- 不绕过 API 直接创建 native backend。

Phase 0 必须确认最终采用 shared callback 还是 RWImGUI managed Context。

============================================================
15. Input Backend / Input Gate
============================================================

RWImGUI 已负责 Win32 ImGui input backend。

因此 DryCycle 不再自行：

- FeedMouse
- FeedKeyboard
- Input.inputString -> io.AddInputCharacter
- io.AddKeyEvent
- io.AddMouseButtonEvent

15.1 Capture state bridge

RWImGUI callback 每帧读取：

ImGui.GetIO().WantCaptureMouse
ImGui.GetIO().WantCaptureKeyboard

将结果写入线程安全 cached flags：

- captureMouse
- captureKeyboard

AIDebuggerRuntime.BlocksPlayerInput 只能读取这些 cached primitive，不跨线程访问 ImGui Context。

15.2 Interact mode

INTERACT：

- Observatory 强制阻断玩家输入。
- UI 可使用鼠标键盘。

LIVE：

- 只有 ImGui 真正 WantCapture 的输入被阻断。
- 未操作 UI 时玩家正常控制。

15.3 F7/F6

F7/F6 仍可由 Rain World 主线程 Unity Input 检测。
原因：

- 不依赖 Render callback 时序。
- Visibility 是 controller/runtime 状态。
- 不需要从 Win32 backend 抢全局热键。

如果后续 RWImGUI 官方提供可靠 hotkey service，可另行评估，但不属于本任务必要条件。

19. Pause / Step / Freeze / Export
============================================================

19.1 Pause / Step

19.2 Freeze / Timeline

但真正“当前使用哪个历史 frame”建议由 command + controller 发布，或者 snapshot 同时提供完整 frames 供 View 纯选择。

无论哪种方案：
不得在 UI callback 读取 live AI 来补历史数据。

19.3 Export

文件 I/O 不在 Present callback 做。

UI：enqueue Export command。
主线程或专门 worker：执行 JSON/文本 export。
完成后通过 snapshot 返回 export result/path。

============================================================
23. Bridge Failure / 降级策略
============================================================

23.1 RWImGUI 未安装

预期：

- DryCycle.dll 正常加载。
- Bridge plugin 被 BepInEx dependency 机制跳过，或主动禁用。
- 仅 Observatory UI unavailable。
- 不影响其它系统。

23.2 RWImGUI 版本不匹配

Bridge 输出一次性 Warning：

- detected API version
- expected tested range
- missing symbol / API mismatch

不得循环抛异常。

23.3 Draw callback exception

捕获 Observatory View exception：

- 记录一次 signature。
- 当前 callback 可以显示最小 error panel 或本帧跳过。
- 不得 destroy RWImGUI global context。
- 不得让其它使用 RWImGUI 的 Mod UI 一起失效。

23.4 DebugSource exception

继续使用现有 Registry fallback：

Specialized Source failure
  -> log once
  -> GenericCreatureDebugSource
  -> UI 继续

28. 性能预算
============================================================

目标不是零开销，而是调试器在关闭时接近零 UI 成本、打开时可控。

关闭：

- 不画 ImGui Observatory widgets。
- 不做高频 snapshot heavy capture。
- Trace 按已有规则决定是否记录。

打开：

- Heavy presentation capture <= 10~20 Hz。
- Present callback 不做 AI traversal。
- Present callback 不做文件 I/O。
- Present callback 不创建大数组。
- UI frame 不复制整个 world object graph。

建议记录：

MainCaptureMs
SnapshotBuildMs
UICallbackMs
CommandQueueDepth
SnapshotAgeMs

如果 queue depth 连续增长：视为 bug。

============================================================
32. 最终原则
============================================================

这次迁移不是“换一个地方调用 ImGui.Begin”。

真正目标是把 AI Observatory 分成两个严格职责：

Rain World 主线程 = 数据与行为控制
RWImGUI Present 层 = 纯 UI 呈现

所有 AI 真值都在主线程产生。
所有 UI 都只消费已经产生的真值。
所有 UI 修改世界的动作都回到主线程执行。

DryCycle 不再拥有 ImGui renderer backend；
DryCycle 只拥有 AI Observatory 产品本身。
