======================================================================
0. 任务定位
======================================================================

本任务不是一个新玩法任务，也不是一次“整理文件夹”式重命名。

本任务的目标是：

1. 回顾并重构当前完整 DesertBatfly 项目；
2. 保持已经批准并实现的生态/AI/社交/天气/战斗行为；
3. 收敛 Task09～Task13 连续追加后形成的跨模块 Hook / Bridge / Reflection / RuntimeDetour 技术债；
4. 建立唯一、明确、可观测的行为控制权与事件流；
5. 去除重复扫描、重复感知、重复事件解释和不必要 Room Runtime；
6. 修复在本轮全项目审查中确认或高度怀疑的隐性 Bug；
7. 重构测试，使测试保护“行为契约”而不是保护历史 Bridge 实现；
8. 为后续 Corpse Ecology、繁殖等新任务提供稳定扩展基础。

本任务完成后，DesertBatfly 应从“多个成熟功能模块通过补丁互相协调”的状态，
进入“多个成熟功能模块通过正式 Runtime / Event / Context / Arbiter 协议协作”的状态。

本任务必须执行“行为保持型重构”。
除任务书明确列出的 Bug 修复外，不得借重构之名改变已批准玩法。

1. 为什么现在必须重构
======================================================================

DesertBatfly 已经包含：

- Creature / State / Personality / Graphics；
- Injury / Shock / Trauma / Grab Memory；
- Harass / Observe / FakeDive / Dive / Attach / Retaliation；
- SandSpit；
- Roost / Fly Chain / platform underside；
- SocialBond / Sex / Grief；
- Extreme Vengeance；
- Peach Lizard 捕食；
- Task09 Colony Migration / Refuge / ReturnHome / World Route；
- Task10 Neutral Social Life；
- Task11 Threat Signature Memory / Current Cue / Tactics；
- Task12 Observable Social Signal Network；
- Task13 Environmental Activity / Shelter / Weather Ecology；
- Observatory / Debug Trace；
- Warp / Sandbox / Watcher compatibility；
- 一套较大的静态/反射式回归测试。

这些功能单独看多数已经成熟。
当前主要问题不是“功能不够”，而是后续 Task 为了不直接修改前一 Task，逐渐形成：

- 一个模块 Detour 另一个模块的私有方法；
- Reflection 读取私有字段；
- DynamicMethod / IL detour；
- frame stamp 阻止另一个模块在某一帧运行；
- 保存/恢复 localGoal 来保护优先级；
- 临时修改持久状态再恢复以影响另一个系统的决策；
- 同一 Room 多套低频扫描器；
- 同一物理/死亡/抓取事件被多个 Hook 分别解释；
- Observatory 只能“猜测”控制权，而不是读取真实控制权。

继续直接新增 Task14/15 功能，会进一步增加 Bridge 数量。
因此本任务优先于后续大型生态功能。

2.1 行为保持
--------------------

重构前已经批准的行为默认必须保持。

特别包括：

- DesertBatfly 体型、外观、花纹、刺、性别差异；

- Task02 Emergent Social Roles 永久否决；
- 不得重新出现 Sentinel / Bully / Opportunist / Leader / Follower / Role enum；
- Rocks 可伤害、可重度眩晕，但单次 Rock Violence 不能直接完成 live -> dead；
- SandSpit；
- Grab struggle；
- Injury / Wing damage / PostStunShock；
- PTSD / GrabMemory / PredatorTrauma；
- SocialBond 单槽、非 N×N 图；
- Grief；
- Extreme Vengeance；
- Peach Lizard 原生 PreyTracker/Hunt/Tongue/Bite/ReturnPrey 管线；
- Task09 跨房生态和路线所有权；
- Task10 Neutral Social Life；
- Task11 Threat Signature 三层语义；
- Task12 恰好六种信号；
- Task13 六阶段环境行为；
- Task13 DryCycle-only weather authority；
- HeavyRain / DeathRain / Fog / DenseFog / Heat / Sandstorm 已批准语义；
- 现有 DesertBatflyState 存档兼容。

2.2 不推倒重写
--------------------

不得把已经工作的 Task09～Task13 全部重新实现。

优先策略必须是：

- 保留纯数学；
- 保留已验证决策规则；
- 保留 bounded cache；
- 保留现有存档格式；
- 替换模块之间的连接方式；
- 删除被新正式 API 取代的旧 Bridge / Detour / dead code。

2.3 内部零 Reflection 原则
--------------------

完成本任务后，DesertBatfly 自己的模块之间不得依赖：

- Reflection 获取另一个 DesertBatfly 模块的 private field；
- RuntimeDetour 挂另一个 DesertBatfly 模块的 private method；
- DynamicMethod / ILGenerator 适配另一个 DesertBatfly 模块；
- 字符串方法名作为内部功能契约。

Reflection / Harmony / RuntimeDetour 只允许出现在真正的外部兼容/游戏 Hook 边界：

- Rain World；
- Watcher；
- Warp；
- 未来第三方 Mod compatibility。

2.4 单一普通飞行所有权
--------------------

普通飞行期间，任何时刻只能存在一个 Primary Movement Owner。

Environment、Social、Threat、Vengeance、Injury 等模块不得各自成为一套普通飞行控制器。

特殊物理状态可明确绕过普通 FlightMotor：

- Emergence；
- Attach；
- Interfere；
- 被抓/约束；
- 碰撞瞬时反冲；
- 攻击瞬时 impulse；
- SandBurst cosmetic；
- 原生 Shortcut/Burrow/Chain 的物理所有权。

2.5 Task09 跨房所有权不得削弱
--------------------

Task09 继续独占：

- EmergencyRefuge destination；
- ReturnHome route；
- ColonyMigration；
- HomeColony change；
- World route planning；
- LeaveRoom；
- abstract movement；
- cross-room weather refuge；
- migration memory/stress/history。

Task13、Task10、Task11、Task12 不得通过本次重构取得跨房移动权。

3. 本轮审查已确认的架构问题与隐性风险
======================================================================

以下问题必须在重构过程中逐项关闭。

3.1 P0：没有真实 Behavior Owner
--------------------

当前 UpdateAI 实际依靠固定调用顺序、return、CancelForPriority、frame stamp、保存/恢复 localGoal 维护优先级。

目标：建立真实 BehaviorArbiter，运行时明确记录当前 Primary Owner。

3.2 P0：Injury Recovery Dijkstra 语义不一致
--------------------

原版 FlyAI / Task13 Home-Hive 路径使用：

    ProgressLocalGoalAlongDijkstraMap(localGoal, map)

当前重伤恢复路径曾使用 body current position 作为推进输入。

这可能造成：

- 重伤返 Hive 短步抖动；
- localGoal 反复靠近身体；
- 狭窄地形方向切换；
- 与原生路径推进互相竞争。

要求：

- 修正 Dijkstra 推进语义；
- Injury 决策不再直接成为第二套普通飞行控制器；
- Injury 仅提交 recovery intent + flight capability modifier。

3.3 P0：Task09 realized drive 潜在同帧重复调用
--------------------

当前 FleeFromRainUpdate 与 UpdateAI 都可能进入 TryDriveRealized。
已有部分 LastObservedFrame 保护，但不是所有 countdown/cooldown 操作都位于同一 guard 后。

要求：

- 每只 DesertBatfly 每个 frame/game clock，TravelRuntime realized tick 最多执行一次；
- Rain hook 不允许再次完整推进同一 TravelIntent；
- 增加自动回归测试验证 DepartureDelay/ReplanCooldown 单帧最多递减一次。

3.4 P0：死亡归因分裂
--------------------

当前 live -> dead 可能分别被：

- DesertBatfly.Die / Intimidation；
- Task11 Creature.Die；
- Hooks.CreatureDie / ColonyRuntime；

使用不同的 killer/cause/time-window 解释。

要求：建立统一 DesertBatflyMortalityEvent。

所有以下模块必须消费同一死亡事实：

- Intimidation；
- ThreatSignature；
- SocialBond / Grief；
- Task12 Signals；
- ColonyRuntime；
- Observatory；
- 后续 Corpse Ecology。

3.5 P0：抓取/Peach Tongue 事件存在多 Hook 路径
--------------------

当前 Core Hooks、Peach integration、Task12 Signal integration 均可能观察 LizardTongue.Update。
现有代码主要依赖下游时间窗去重。

要求：

- Peach/other capture 只检测一次；
- 生成统一 CaptureEvent；
- Intimidation/Signals/Injury/Social/Threat 各自订阅；
- 不再靠多 handler 重复 Threatened 后由幂等兜底。

3.6 P0：CorpseWarning 生命周期残留
--------------------

Intimidation 的短期 Room object 在 Reset/Disable 时缺少集中销毁所有权。

要求：

- 不再生成无法被 runtime 集中追踪的 DesertBatfly ecology Updatable；
- 若保留 transient object，必须登记到 RoomRuntime 并在 Disable/Room teardown 清理；
- 优先把 death-site warning 状态迁入 RoomEcology/Event runtime，而不是每次死亡 new 自治 Update object。

3.7 P1：Task13 临时改写 Thirst 传递攻击动机
--------------------

当前环境 integration 曾通过：

    save Thirst
    set decision Thirst
    ScanCreatures()
    restore Thirst

把 HeatAgitation/Harass multiplier 注入旧 AI。

要求：删除该机制。

新增明确 MotivationContext：

- HydrationDrive；
- HeatAgitation；
- GriefAnger；
- RetaliationDrive；
- SocialHarassDrive；
- EnvironmentalDefenseDrive；
- PhysicalCapability / Exhaustion modifier。

任何决策不得临时篡改持久 CreatureState 作为函数参数。

3.8 P1：旧感知与 Task11 感知重复
--------------------

当前旧 AI ScanWeapons、Task11 thrown weapon cache、DenseFog fallback 可能分别扫描 weapons。

要求：

- 建立统一 RoomPerception weapon cache；
- 普通 AI / Task11 / Fog fallback 读取同一真实 weapon observation；
- close projectile safety 保留；
- 不读取玩家输入或隐藏意图。

3.9 P1：旧 social harass 逻辑被 Task12 detour 遮盖
--------------------

旧 FindSocialHarassTarget 通过读取邻居 DesertAI.Target / Mode 实现 contagion；
Task12 已批准 HarassSignal 替代该信息传播。

要求：

- 删除被 Task12 正式信号网络取代的旧邻居私有状态窥探路径；
- 不保留两套同时可用的 harass contagion。

3.10 P1：Task12/Task13 参数复制
--------------------

VisualRadius / AcousticRadius 等信号参数不得在 Fog bridge 再复制一套。

要求：

- SignalDefinition 成为唯一 signal range authority；
- Task13 只提供 VisibilityMultiplier/Perception modifier；
- 调整 Task12 参数时无需同步修改 Task13 常量。

3.11 P1：Room runtime 不够惰性
--------------------

当前部分 Room.Update 路径会对没有 DesertBatfly 的 realized room 创建 Signal/Environment/Refuge 数据。

要求：

统一 DesertBatflyRoomContext 激活条件。

仅在以下情况之一成立时建立/更新昂贵 room state：

- 房间存在 realized DesertBatfly；
- 房间属于 Desert colony/home；
- Task09 明确查询该房间生态；
- Observatory 明确请求该房间 debug；
- 某个真实 DesertBatfly event 临时需要。

不得让普通地图房间仅因 Room.Update 就扫描 shelter terrain。

3.12 P1：测试保护了 Bridge，而非行为
--------------------

现有部分测试通过：

- MethodCallOffset；
- xxxBridge 必须存在；
- xxxHook 必须存在；
- MarkTravelOwnedFrame 必须被调用；

保护当前实现。

重构时必须改为测试：

- Priority contract；
- ownership contract；
- event exactly-once；
- save compatibility；
- behavior math；
- forbidden side effects；
- no internal reflection；
- no duplicate travel tick。

5. 新核心：DesertBatflyFrameContext
======================================================================

每次 DesertBatfly realized AI update 开始时，构造一个只描述“当前帧事实”的 context。

至少包括：

Identity:
- Bat；
- EntityID；
- Room；
- Tick / Frame；

Physical:
- Position；
- Velocity；
- Conscious；
- Dead；
- Restrained；
- InShortcut；
- InHive；
- Current Fly movement mode；
- Current FlyAI behavior；

Individual:
- Personality；
- PhysicalCapability；
- Injury severity；
- PostStunShock；
- Hydration / Thirst；
- Trauma；
- Grief；
- SocialBond summary；

Perception:
- nearest visible Player；
- current predator threat；
- validated thrown weapon observations；
- incoming projectile cue；
- room visibility factor；

Ecology:
- Task09 TravelIntent summary；
- Task12 SignalInfluence；
- Task13 EnvironmentalInfluence；
- room flock snapshot；
- room shelter summary；

Rules:
- HardSurvival；
- CombatAllowed；
- SocialAllowed；
- CrossRoomOwned；
- SpecialPhysicsOwner。

Context 只用于当前帧/决策周期，不存档。

模块不得为了拿信息而 Reflection 另一个模块 private state。

6. 新核心：Behavior Proposal / Arbiter
======================================================================

6.1 Proposal contract
--------------------

每个行为模块可提交一个或多个 proposal。

建议字段：

DesertBatflyBehaviorProposal
- Owner；
- Priority；
- BehaviorKind；
- Goal；
- NominalSpeed；
- DesiredFlyBehavior（optional）；
- DesiredDijkstraMap（optional）；
- RequestBurrow；
- SuppressCombat；
- SuppressSocial；
- PreserveExistingGoal；
- ValidUntilTick / commitment；
- Reason；
- DebugSource。

Proposal 本身不得直接写 BodyChunk.vel。

6.2 Primary Owner priority
--------------------

推荐总体优先级保持现有批准语义：

1. Death / unconscious / destroyed；
2. Special physical restraint / grabbed / shortcut / emergence；
3. Immediate physical danger / escape；
4. Severe Injury / InjuryRecovery；
5. Task09 realized cross-room Travel；
6. Task13 Acute HardSurvival；
7. PTSD / direct threat reaction；
8. Extreme Vengeance；
9. Task13 Preparation/Sheltering local survival；
10. projectile evade tactical modifier / immediate cue；
11. Formal Harass / Retaliation / Attack；
12. Roost / Chain；
13. Task10 Neutral Social Life；
14. ordinary DesertBatfly idle/swarm behavior；
15. Vanilla FlyAI fallback。

注意：

- 具体数值可实现为 enum rank，不要求 magic int；
- Task09 “有 intent 但当前因抓取/重伤 suspended”不应自动击败更高优先级；
- HardSurvival 可暂停 Vengeance，但不能清除 Vengeance memory；
- Task12 永远不应成为 locomotion owner；
- Task11 Threat Signature memory 本身永远不应成为 locomotion owner；
- Task13 visibility/navigation uncertainty 应作为 modifier，而不是第二 Primary Owner。

6.3 Arbiter result
--------------------

每帧只产生一个 ResolvedBehavior：

- PrimaryOwner；
- WinningProposal；
- Modifiers；
- final Goal；
- final NominalSpeed；
- final Dijkstra ownership；
- final Combat/Social gates；
- reason；
- rejected proposals + reject reason（debug only）。

7. 新核心：FlightMotor
======================================================================

FlightMotor 是普通 DesertBatfly 飞行的唯一最终执行入口。

职责：

- 接受 Arbiter final goal；
- 设置 FlyAI.localGoal / native steering intent；
- 接受 nominal speed；
- 应用 Injury Forward/Turn/Lift/Acceleration modifier；
- 保持 native Fly collision / movement pipeline；
- 不实现第二套 path planner；
- 不 teleport；
- 不固定 Y；
- 不直接绕过 terrain collision。

Task13 Fog navigation error：

- 作为 goal modifier；
- 在 FlightMotor 前完成；
- 不自己写 velocity。

Injury：

- InjuryDecision 提交 recovery proposal；
- InjuryFlightModifier 最终修改 native requested flight；
- 不在 InjuryRecovery 中持续独立写 vel。

8. 特殊物理所有权
======================================================================

以下行为允许明确绕过普通 FlightMotor：

8.1 Emergence
- 可使用 MoveFromOutsideMyUpdate；
- 可临时关闭 collision；
- 结束时恢复 collision；
- 必须在 Cancel/Destroy/Room transition 恢复。

8.2 Attach / Interfere
- 可将 bat 约束到 target BodyChunk；
- 可同步目标 velocity；
- 可对目标施加批准的 drag/impulse；
- 必须有显式 enter/exit lifecycle；
- 退出后重新交还 FlightMotor。

8.3 Hit / retaliation impulse
- 瞬时 impulse 允许直接写 velocity；
- 不得演变成多帧普通飞行控制器。

8.4 Native Burrow / Chain / Shortcut
- 原生 Rain World system 为物理 owner；
- Arbiter 只决定是否请求进入；
- 不替代原生执行。

11. 统一 CaptureEvent
======================================================================

抓取检测与生态反应分离。

Detection：

- Player grasp；
- Peach tongue attach；

12. 统一 RoomPerception / RoomContext
======================================================================

目标：减少“一房间五套扫描器”。

12.1 Active bats cache
- 维护有效 realized DesertBatfly list；
- dead/slated/inShortcut/inHive 可按不同 view 过滤；
- Task10/11/12/13 不再各自完整枚举 colony list。

12.2 Players cache
- 当前 room player list；

36. 最终架构目标
======================================================================

重构完成后，新增一个 DesertBatfly 功能时，理想流程应是：

1. 新模块读取 FrameContext / RoomContext；
2. 若只是信息层，输出 influence/event；
3. 若需要移动，提交 BehaviorProposal；
4. Arbiter 决定是否获得当前帧所有权；
5. FlightMotor/native FlyAI 执行；
6. 事件通过 EventHub 发布；
7. Observatory 自动看到 owner、proposal、event；
8. 不需要为了接入旧模块再写 private Reflection/Detour/IL bridge。

这才是本任务真正的成功标准。

本任务不是为了让文件看起来更整齐，
而是为了让 DesertBatfly 在继续扩展数十个生态功能后，仍然能够：

- 明确谁拥有决策；
- 明确谁拥有移动；
- 明确事实从哪里产生；
- 明确谁可以修改什么状态；
- 明确哪些行为必须保持；
- 明确性能预算；
- 明确失败时在哪里调试。
