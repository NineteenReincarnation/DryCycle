Desert Batfly Task 09
Colony Migration + Weather Refuge + Cross-Room Navigation
群落迁徙 + 天气避难 + 跨房间寻路
Codex Execution Specification
============================================================

0. 任务性质
============================================================

这是 Desert Batfly 第 09 项的正式可执行任务书。

本任务目标不是制作一个“人口数字随机变化器”，也不是给 FlyAI 再造一套飞行控制器，而是建立一个与 Rain World AbstractCreature / AbstractRoom 世界层兼容的群落生态系统，使 Desert Batfly 能够：

1) 在长期高死亡、Peach 长期捕食、持续环境不适合等条件下形成群落级迁徙压力；
2) 以小批次、真实个体的方式从一个 DESERTSWARMROOM 迁往附近更合适的 DESERTSWARMROOM；
3) 迁出后不永久绑定“出生地”，未来条件变化时允许自然回迁或再次迁往其他群落；
4) 在整个区域普遍遭遇 DangerType / 危险天气时，不把“所有巢穴都危险”错误解释成群落之间无限互迁，而是优先进入临时避难流程；
5) 当本巢不足以抵御危险天气时，提前前往附近安全 Refuge，天气结束后返回 Home Colony；
6) 使用世界图层的跨房间路线规划决定“去哪、经过哪些房间”，但房间内部的具体飞行、出口接近和 shortcut 行为继续尽量复用原版 FlyAI / AI map / Dijkstra；
7) 在任何环境下保留最低限度的群落恢复能力，避免某个 DESERTSWARMROOM 因一次灾害后永久变为空房；
8) 保持个体 EntityID、Personality、Sex、SocialBond、Trauma、Grief、Wing Injury 等连续性，迁徙不能把真实个体替换成随机新个体。

本任务是生态层、abstract world 层和 realized AI 层之间的桥接任务。

【必须】先重新读取 main 当前实现；如果本任务书与之后 main 已发生的代码重构冲突，以“本任务书的行为目标 + main 当前架构”共同决定实现，不允许机械恢复旧代码。

============================================================
2. 三个时间尺度必须严格分层
============================================================

2.1 即时危险 / Immediate Survival
-----------------------------------
尺度：秒级、当前 realized room。

例如：
- Peach 正在攻击；
- 玩家正在抓取 / 投矛；
- 当前 IntenseHeat / Sandstorm 已经产生致命暴露；
- 当前房间存在直接捕食者。

这一级继续由现有 Fear / Escape / Trauma / Injury 等优先处理。


2.2 天气避难 / Weather Refuge
--------------------------------
尺度：当前天气事件前后，分钟级，可跨若干房间。

目标：
- 预报危险天气；
- 判断 Home Hive 是否足够安全；
- 若不安全，则提前转移至 Emergency Refuge；
- 危险结束后返回 Home Colony。

这不是永久迁徙。


2.3 群落迁徙 / Colony Migration
--------------------------------
尺度：跨 Cycle、生态级。

只有长期证据才允许推动迁徙：
- 持续高死亡；
- Peach 长期驻留/重复成功捕食；
- 多个 Cycle 的反复天气庇护失败；
- 某巢穴相对附近其他群落明显更差。

单次 HeatWave、一次 Peach 路过、一次死亡都不能直接触发永久迁徙。


============================================================
3. 核心群落状态：DesertBatflyColonyState
============================================================

Task 09 应建立跨 realization / 跨 Cycle 的轻量群落账本。

建议职责单一的新结构，例如：
- DesertBatflyColonyState
- DesertBatflyColonyRuntime

具体命名可按 main 风格调整。

每个 DESERTSWARMROOM 至少需要逻辑状态：

- RoomName / stable room identity
- CurrentPopulation / 当前真实归属人口
- PreferredPopulation / 健康群落理想人口
- SoftCapacity / 软容量
- HardMinimumPersistence / 最低生态保底
- NaturalRecoveryCeiling / 当前背景自然恢复上限

长期压力：
- MortalityPressure : 0..1
- PredatorPressure : 0..1
- EnvironmentalPressure : 0..1
- ShelterFailureMemory : 0..1
- MigrationPressure : 0..1（可派生或半持久）

迁徙节流：
- LastMigrationCycle
- ColonyMigrationCooldown
- 最近一次迁出批次 / 迁入批次的必要轻量统计

天气/避难：
- RecentWeatherStress
- LastSuccessfulRefuge（可选，房间/节点级轻量记忆）
- ConsecutiveBadWeatherCycles 或等价低成本连续性状态

禁止：
- 每帧跨区域扫描所有群落；
- 每个 Colony 保存完整历史事件列表；
- 保存 N×N 群落关系矩阵。


============================================================
4. 人口语义：真实个体 + 背景生态恢复
============================================================

4.1 真实个体连续性
-------------------

永久迁徙中的个体必须保持同一只：
- EntityID
- Personality
- Sex
- SocialBond
- Trauma / PTSD
- Grief
- LeftWingInjury / RightWingInjury
- 其他 DesertBatflyState 持久状态

禁止：
A.population--
B.population++
然后在 B 生成一个完全新的随机 Personality 个体。

迁徙必须尽量转移同一个 AbstractCreature / 对应持久身份。


4.2 背景自然恢复允许存在
------------------------

与早期“绝不自动补人口”草案不同，最终决定：

【硬规则】即便环境恶劣，DESERTSWARMROOM 也必须保留最低限度的群落恢复能力。

理由：
- Task 05B 繁殖尚未实现；
- 如果完全依赖迁入，一个群落被杀空后可能永久消失；
- 地图生态需要长期可恢复性。

背景恢复不是完整繁殖系统。
可以抽象理解为：
- 未模拟的小型巢穴补充；
- 未追踪个体回流；
- 幼体自然长成但未进行完整生命周期模拟；
- 区域背景种群补充。

不要在 HUD 或文本中解释具体来源。


4.3 四个人口尺度
----------------

建议每个 Colony 使用：

HardMinimumPersistence
- 即使长期恶劣，也非常缓慢尝试恢复到的最低生态底线。
- 初始调参建议：正常中型群落 2~4，只作为量级参考。

NaturalRecoveryCeiling
- 仅靠背景恢复当前最多恢复到哪里。
- 环境越差越低，但普通恶劣条件下不得归零。

PreferredPopulation
- 健康群落理想人口，例如地图原设计数量附近。

SoftCapacity
- 超过后降低迁入吸引力、增加拥挤惩罚；不是硬上限。

示意：
HardMinimumPersistence = 3
NaturalRecoveryCeiling = 8
PreferredPopulation = 14
SoftCapacity = 18

数值必须根据实际地图群落规模归一化，不得硬编码所有房间固定 3/8/14/18。


4.4 恢复速度
------------

恢复必须慢，不能一次补齐。

原则：
- 每个 Cycle 最多背景补充极少个体；
- 高压力下成功率更低；
- 正在发生致命天气时禁止实时 spawn；
- 恢复在 Cycle / abstract ecology 结算发生；
- 环境恶劣时可例如 10%~40% 级别尝试补 1，只作为初始调参范围；
- 安全环境可更高，但仍不能瞬间从 1 跳回 PreferredPopulation。

示例：
Population = 1
HardMinimumPersistence = 4
高压力环境下可能：
Cycle 1: 1
Cycle 2: 2
Cycle 3: 2
Cycle 4: 3
Cycle 5: 4

而不是 1 -> 4。


4.5 背景恢复不得破坏迁徙意义
----------------------------

如果原群落 14 只，灾害后剩 2 只，当前恶劣环境 NaturalRecoveryCeiling = 4：
只能缓慢恢复到约 4，然后停住。

环境改善后 NaturalRecoveryCeiling 才逐步提高。

健康环境下背景恢复也不应默认直接补满 PreferredPopulation；理想设计是：
- 低人口区可以靠背景恢复到中低水平；
- 更高的人口繁荣主要由迁入、回迁，以及未来 05B 繁殖共同完成。


============================================================
5. 三类长期压力
============================================================

5.1 MortalityPressure / 死亡压力
--------------------------------

来源：
- 当前 Cycle 群落真实死亡数；
- 最近多个 Cycle 连续死亡；
- 当前人口相对健康人口显著下跌。

原则：
- 1 只偶发死亡影响很弱；
- 连续多个 Cycle 都发生死亡比一次短时波动更能证明“这里长期不安全”；
- 一次大屠杀后的短期 shock 可以很高，但幸存人口已很少时不能无限重复叠加。

必须避免同一死亡事件重复计数。


5.2 PredatorPressure / 捕食者压力
----------------------------------

初始重点：Peach。

不允许：
room 中只要存在 Peach -> 每帧永久加压力。

应根据低频事件/汇总指标：
- Peach 在群落房停留时长；
- 重复进入次数；
- 成功捕食 Desert Batfly 次数；
- 是否长期占据 Hive / 出巢附近；
- 是否连续多个 Cycle 返回。

示意：
- Peach 路过 10 秒：近乎无长期影响；
- Peach 待大半个 Cycle：明显影响；
- 连续多个 Cycle 成功捕食：强影响；
- 长期守 Hive：极强影响。

未来其他捕食者可通过统一接口加入，不能把系统写死为仅 Peach。


5.3 EnvironmentalPressure / 环境长期压力
-----------------------------------------

只记录“房间真实经历过的环境压力”。

天气 schedule 中存在某事件本身不等于该房间实际受影响。
必须使用 WeatherSpatial 等系统之后的最终 local intensity / exposure。

概念：
WeatherExposure = ∫ LocalIntensity(t) × EcologicalSeverity dt

EnvironmentalPressure 跨 Cycle 缓慢积累和衰减。

天气结束后不能瞬间归零。


============================================================
6. 天气系统：Task 07 与 Task 09 的边界
============================================================

6.1 天气预报不直接增加迁徙压力
--------------------------------

Weather schedule 的未来信息只用于：
- 提前回巢；
- 判断是否需要 Emergency Refuge；
- 判断是否来得及撤离。

预报本身不能增加 EnvironmentalPressure。
只有实际发生并作用于该房间的天气才能形成长期环境记忆。


6.2 当前天气类型的初始生态分类
-------------------------------

以下是初始设计方向，不要求把 ID 永久硬编码在 DesertBatflyAI 中；应通过统一 Weather Ecology API 暴露语义。

LightRain
- 即时影响很低；
- 基本不产生长期迁徙压力。

Fog
- 可影响视觉/活动；
- 基本不驱动迁徙。

DenseFog
- 可增加短期保守行为；
- 长期迁徙压力极低或 0。

HeavyRain
- 中高即时避难倾向；
- 只有频繁、长时间出现才产生低~中长期压力；
- 不应成为主要迁徙驱动。

HeatWave
- 主要是慢性环境压力；
- 连续多个 Cycle 尤其重要；
- 明显降低群落恢复上限/迁入吸引力。

Sandstorm
- 高即时避难；
- 高长期环境压力；
- 连续发生尤其容易产生 ShelterFailure。

IntenseHeat
- 灾害级即时危险；
- 单次即可留下明显环境压力；
- 但不能一场天气直接让整群永久搬家。

DeathRain / DeathSandstorm
- 灾害级；
- 高度依赖提前预警；
- 天气已经完全开始后通常不应再启动长距离撤离；
- 若个体没赶上并死亡，死亡由 MortalityPressure 独立记录，避免同一结果三重计数。


6.3 建议统一天气生态接口
------------------------

禁止 DesertBatflyAI 到处：
if (HeatWave)
if (IntenseHeat)
if (Sandstorm)
...

建议 Weather 层提供类似：

WeatherEcologySample
{
    ActiveIntensity
    ImmediateDanger
    ShelterUrgency
    MigrationStress
    TravelExposure
}

具体类型/命名可以调整。

目标：未来新增天气时主要扩展 Weather Ecology 映射，而不是继续污染 DesertBatflyAI。


============================================================
7. 区域级灾害与相对栖息地压力
============================================================

关键问题：如果整个区域所有 DESERTSWARMROOM 都受到同一 DangerType，不能产生：
A -> B -> C -> A
无限互迁。

因此必须区分：

RegionalWeatherStress
- 整个区域近期普遍糟糕；
- 影响恢复率、活动、庇护需求、总体繁荣；
- 不应直接强推群落之间迁徙。

RelativeHabitatStress
- 当前巢穴相对附近其他可居住 Colony 明显更差；
- 这才是天气驱动永久迁徙的核心部分。

示例：
A=0.82, B=0.79, C=0.85
=> 区域都很糟，A 并没有明显更差；优先临时避难，不应因为绝对 0.82 就迁 B。

A=0.80, B=0.25, C=0.30
=> A 相对明显更差，长期存在真实迁徙意义。

实现不要求严格使用 Local - RegionAverage 这一唯一公式，但必须保持“相对比较”语义。


============================================================
8. Hive Shelter Quality / 巢穴庇护质量
============================================================

危险天气发生时，首先判断“本巢能不能扛”，而不是立刻外逃。

每个 Colony 应可得到：
HiveShelterQuality : 0..1

它表示该 DESERTSWARMROOM 的 Hive / 主要栖息区对当前危险的有效保护能力。

注意：庇护质量可以是“针对某类危险的有效值”，不一定一个常数对所有天气相同。

应考虑：
- 是否位于地下/室内；
- 对 direct solar exposure 的遮蔽；
- 对 Sandstorm / DeathSandstorm 的阻挡；
- 对暴雨的遮挡；
- Hive 所在 tile/node 周围实际暴露；
- WeatherSpatial 对该位置的最终影响。

不应把 environmentalLight 当作庇护判定本身。

优先实现：
- 自动从实际空间暴露/位置判断；
- 允许地图作者通过轻量配置/PlacedObject/RoomSettings 覆盖或修正自动值；
- 手动标记是 override，不应要求所有地图都手写 Refuge 路线。


============================================================
9. ShelterFailureMemory / 巢穴反复失效
============================================================

DangerType 本身不直接等于长期迁徙压力。

天气导致永久迁徙的核心桥梁是：
Repeated Shelter Failure / 反复庇护失败。

ShelterFailureMemory 增加条件：
- 群落被迫离开 Home Hive 去外部 Refuge；
- Hive 内仍然处于高危险暴露；
- 因 Home Shelter 不足导致个体死亡；
- 连续多个 Cycle 都必须外部撤离。

一次撤离只增加少量。
多次连续撤离才明显提高。

天气结束后 ShelterFailureMemory 缓慢衰减，不瞬间清空。

永久迁徙应更接近：
天气 -> Home shelter 不够 -> 被迫反复撤离 -> ShelterFailureMemory -> RelativeHabitatStress -> MigrationPressure

而不是：
HeatWave -> MigrationPressure + 0.2。


============================================================
10. Emergency Refuge / 临时避难所
============================================================

10.1 Refuge 不是 Colony
-----------------------

普通房间即使没有 DESERTSWARMROOM，也可以成为 Emergency Refuge。

Refuge 只用于临时避灾。
它不能因此获得：
- Colony population；
- PreferredPopulation；
- NaturalRecovery；
- 普通迁徙目的地身份；
- 永久 Home Colony 身份。

天气结束后，避难个体默认返回自己的 Home Colony。


10.2 Refuge 必须是房间 + 安全区域
---------------------------------

不能只存 RoomName。

一个房间可能上半部暴露、下半部安全。
建议 Refuge target 逻辑表示为：
- RefugeRoom
- RefugeNode / RefugeZone / safe coordinate set

实际结构按 Rain World abstract node / AI map 可用能力决定。


10.3 Refuge 候选条件
--------------------

候选至少满足：
- 同一区域；
- 世界图可达；
- 当前危险下实际安全性显著高于 Home；
- 路线在预警时间内有机会到达；
- 不是明显致命中转区；
- 最终区域有真实可用遮蔽。

Refuge 搜索半径应明显小于长期 Migration 目的地搜索。
初始建议：世界图 1~3 房间，必要时允许少量扩展；实际按地图结构调参。


10.4 Refuge Quality
-------------------

建议评分：
RefugeScore =
    ShelterQuality
  - TravelCost
  - CurrentDanger
  - PredatorRisk
  - CrowdingPenalty

不能只看终点安全，还必须看 RouteSurvivability。


10.5 Refuge Soft Capacity
-------------------------

一个 Refuge 可以接纳多个 Colony 临时避难。

允许出现：
Colony A \
          -> CAVE_X
Colony B /

但 Refuge 可有 SoftRefugeCapacity / crowding penalty，避免所有群落永远挤同一个点。

容量不是硬禁止：灾害中宁可拥挤，也不能因为“容量满”把可生存个体留在致命环境中。


10.6 Known Refuge / 成功避难记忆
--------------------------------

Colony 可以轻量记忆最近一次成功避难点。

同类型危险再次出现时：
- 已成功使用过的 Refuge 获得轻微 Familiarity bonus；
- 不能成为绝对锁定；
- 若路线或 Refuge 当前变危险，必须允许改道。


============================================================
11. 天气预警与撤离时机
============================================================

完整流程：

Danger forecast
    ↓
Evaluate Home Hive Shelter
    ↓
Home 足够安全？
  Yes -> 回巢/留巢
  No  -> 搜索 Emergency Refuge
            ↓
      存在安全且来得及到达的路线？
          Yes -> 分批提前撤离
          No  -> 留在 Home / 当前最近的本地最佳遮蔽，不进行必死长途逃亡


11.1 旅行时间估算
-----------------

必须估算：
EstimatedTravelTime(route)

至少考虑：
- 房间跳数；
- shortcut 转移基础成本；
- 房间大小/典型出口接近成本的近似；
- Injury 对旅行能力的修正；
- 当前路线天气暴露。

不要求精确到每帧，但必须足够保守。

只有：
EstimatedTravelTime + SafetyMargin < TimeUntilDanger
才允许正常启动长距离 Emergency Refuge。


11.2 已经太晚时
---------------

如果 DeathRain / IntenseHeat 等危险已完全进入致命阶段，而安全 Refuge 需要跨多个房间：
- 不应突然让整群开始长途跑；
- 优先 Home Hive / 当前房间最佳本地庇护；
- 没赶上的真实死亡正常发生并进入 MortalityPressure。


============================================================
12. 永久 Colony Migration / 群落迁徙
============================================================

12.1 迁徙触发是长期、复合的
----------------------------

MigrationPressure 应来自：
- MortalityPressure；
- PredatorPressure；
- RelativeHabitatStress；
- ShelterFailureMemory；
- 可选的低权重人口/栖息地适宜性修正。

禁止把 Resource Pressure 偷偷接入当前版本。

MigrationPressure 建议 0..1，并使用滞回。

概念阈值（初始调参，不是最终常量）：
- BeginMigration > ~0.70
- ContinueMigration > ~0.55
- StopMigration < ~0.40

必须通过 hysteresis 避免阈值附近来回切换。


12.2 小批次迁移
---------------

禁止整群瞬间搬空。

一次迁移建议：
- 小群落：1 只；
- 中群落：1~3 只；
- 大群落：约 10%~20%，受最小/最大批次 clamp。

实际数值应与当前 Population / HardMinimumPersistence 联动。

正常迁徙不能把群落降到 HardMinimumPersistence 以下。
极端长期灾难是否允许最终 Colony Collapse，可以预留，但默认 V1 不以“彻底灭绝”作为常规结果。


12.3 个体迁出倾向
-----------------

不能完全随机，也不能创建 Migrator Role。

更容易迁出：
- RoostAffinity 较低；
- Conformity 较低或中低；
- 对当前 Colony 的 Trauma / 近期危险经历较高；
- 身体健康、具备旅行能力；
- 最近多次经历 ShelterFailure。

更不容易迁出：
- RoostAffinity 高；
- 严重 Wing Injury；
- 当前仍在 InjuryRecovery；
- 强 SocialBond partner 留在 Home；
- 刚完成迁徙且处于 cooldown。

这些必须是连续权重，不允许正式社会角色 enum。


12.4 SocialBond 与同行
----------------------

如果 A 被选中迁徙，而 A 对 B 的 Bond 很强：
- A 的迁出概率可以略降；
- 或 B 获得轻微同行倾向。

禁止：
A 拉 B，B 再拉 C，形成无限链式整群迁徙。

最多基于每只现有单槽 SocialBond 做有限影响。


============================================================
13. 迁徙目的地选择
============================================================

13.1 只允许同一区域
-------------------

V1 永久迁徙目标必须：
- 同一区域；
- 是 DESERTSWARMROOM；
- World graph 可达。

禁止跨区域自动迁徙。


13.2 “邻近”是世界图距离，不是必须直接相连
-------------------------------------------

两个 Colony 中间可以夹普通房间。

目标搜索可使用 World graph 的 BFS / Dijkstra / A*，例如限制若干 room hops。
初始永久迁徙搜索范围可约 3~5 个房间，按地图结构调参。


13.3 Destination Suitability
----------------------------

建议：
DestinationScore =
    HabitatSuitability
  + FreeCapacity
  + FormerColonyFamiliarity
  + BondPartnerPresence
  - PredatorPressure
  - MortalityPressure
  - EnvironmentalPressure
  - ShelterFailureMemory
  - TravelCost

禁止偷看未来随机 Weather schedule。

可使用：
- 已发生的长期天气历史；
- 当前可感知/即将发生天气，仅用于当前旅行安全；
- 稳定的房间庇护/环境属性。


13.4 人口容量是软约束
---------------------

当前人口明显高于 SoftCapacity 的 Colony：
- 迁入吸引力明显下降；
- 但不是绝对禁止。

这只是防止所有个体往同一个群落堆积，不是 Task 06 Resource Pressure。


============================================================
14. 回迁 / 再迁徙
============================================================

迁出后允许未来回到旧群落，但绝不做“自动回出生地”。

每次迁徙完成后：
- 新 Colony 成为 Current/Home Colony；
- 旧 Colony 只保留轻量 Familiarity；
- 后续如果新 Colony 恶化，而旧 Colony 已恢复安全，可自然回迁；
- 也可以迁往第三个 Colony。

建议个体只保留必要历史：
- CurrentColony
- PreviousColony（可选）
- LastMigrationCycle

禁止保存完整 A->B->C->D... 迁徙历史。

FormerColonyFamiliarity 必须是轻微 bonus。
不能让个体无视旧 Colony 当前危险强行“回老家”。


14.1 迁徙冷却
---------------

个体完成永久迁徙后，普通情况下至少 2~4 Cycle 不再次参与迁徙。

Colony 本身也应有 1~数 Cycle 的批次节流，避免每 Cycle 大量搬家。

严重灾难可允许打破部分冷却，但必须是罕见紧急逻辑。


============================================================
15. 跨房间寻路总架构
============================================================

Task 09 必须新增“世界图路线规划”，但禁止重写房内 Fly locomotion。

推荐架构：

Colony / Weather Ecology
        ↓
Destination Selector
        ↓
Abstract World Route Planner
Weighted Dijkstra / A*
        ↓
[room, room, room ...]
        ↓
Travel Navigation State
Current NextRoom
        ↓
Vanilla FlyAI / AbstractCreatureAI
        ↓
Native room AI map / Dijkstra
        ↓
Shortcut
        ↓
Next Room

【核心原则】
我们负责：
- 去哪里；
- 经过哪些房间；
- 什么时候重规划；
- 当前 next room 是谁。

原版负责：
- 当前房间具体怎么飞；
- 如何接近正确出口；
- 如何进入 shortcut；
- 原版可用情况下如何使用 native Dijkstra / FlyAI.LeaveRoom / AbstractCreatureAI path。

禁止构建跨所有房间 tile 的大 A*。


============================================================
16. World Route Planner / 世界图带权寻路
============================================================

16.1 不是简单 BFS
-----------------

最少 room hop 不一定最安全。

例如：
Route A: 2 房间，但穿过 IntenseHeat 1.0 暴露房。
Route B: 3 房间，但全部相对安全。

Emergency Refuge 应优先 Route B。


16.2 房间/边 Travel Cost
------------------------

可基于：
BaseDistance
+ WeatherExposure
+ LethalDanger
+ PredatorRisk
+ TraversalDifficulty
+ Congestion

不同 TravelPurpose 使用不同权重。


16.3 TravelPurpose
------------------

至少：
- EmergencyRefuge
- ReturnHome
- ColonyMigration

EmergencyRefuge：
安全 > 到达时间 > 距离。

ReturnHome：
安全 + Home / familiar route + 距离。

ColonyMigration：
DestinationSuitability > 合理距离，路线安全仍必须达标。

三种目的共享一个 route planner，不写三套寻路器。


16.4 路线必须评估 RouteSurvivability
------------------------------------

安全终点不代表可用 Refuge。

如果到 Refuge 必经房间正在致命天气下暴露：
- 当前路线应被判为高风险/不可达；
- 尝试替代路径；
- 没有安全路径时回退到 Home/local shelter。


============================================================
17. 房内路线执行
============================================================

17.1 复用原版 FlyAI
-------------------

优先核对并复用原版：
- FlyAI.LeaveRoom(WorldCoordinate) 或等价入口；
- NodeInALeadingToB / abstract room connection 逻辑；
- followingDijkstraMap；
- room AI map；
- shortcut entrance。

禁止为 Task 09 直接通过：
- 每帧写 mainBodyChunk.vel；
- 长时间强制 localGoal；
- 自己维护整房 tile-level 第二套路径图；
来控制“跨房飞行”。

社会角色系统曾因直接控制 localGoal/velocity 出现明显机械飞行，Task 09 不得重复该问题。


17.2 中间房间续接
-----------------

路线：
A -> B -> C -> Refuge

到 B 后：
- CurrentRouteIndex 更新；
- NextRoom = C；
- 原版 FlyAI 被要求离开 B 前往 C；
- 进入 shortcut 后继续。

不要因为到达中间房间就重新选择整个目的地，除非触发明确 Replan 条件。


============================================================
18. TravelIntent 与 DesertBatflyAI.Activity 分层
============================================================

现有 Activity 是当前房间低层行为，例如：
- Flight
- Observe
- Approach
- Escape
- Roost
- InjuryRecovery

跨房旅行不应把这些全部塞成 Activity enum 的巨大扩展。

建议独立高层状态：

TravelIntent
{
    None,
    EmergencyRefuge,
    ReturnHome,
    ColonyMigration
}

以及旅行阶段：
- Planning
- TravelToExit
- InShortcut
- TransitRoom
- Arrived
- SuspendedByThreat
- RouteBlocked
- Replanning

高层 TravelIntent 决定长期目标。
低层 Activity 仍负责当前 realized behavior。


============================================================
19. 旅行中的行为打断与恢复
============================================================

即时生存优先级必须高于旅行。

如果迁途中遇到：
- Predator；
- 玩家直接攻击；
- 抓取；
- 其他即时致命威胁；

应：
Travel route 保留
-> 暂停 Travel
-> 进入现有 Escape / survival behavior
-> 威胁解除
-> ResumeRoute

不要每次被吓一下就清空最终目的地。

建议使用 TravelSuspended 语义，而不是 Cancel。


============================================================
20. Injury 与旅行优先级
============================================================

严重 Wing Injury 必须降低旅行可行性。

例如：
- 严重单侧伤；
- 双侧重伤；
- InjuryRecovery active；
- PostStunShock 很高；

不能因为天气预警就强迫其完成多房间高风险撤离。

处理：
- 增加 EstimatedTravelTime；
- 降低 RouteSurvivability；
- 更偏向近距离 Refuge；
- 必要时留在 Home / local shelter。

建议优先级：
1) 即时致命危险
2) 严重伤病 / 无法正常旅行
3) EmergencyRefuge
4) ReturnHome
5) ColonyMigration
6) 普通 Roost
7) 普通社交/骚扰/观察


============================================================
21. 群体共享路线，但个体不齐步走
============================================================

21.1 Colony-level route cache
-----------------------------

如果 Colony A 有 18 只蝠蝇，不允许 18 只每几十帧各自跑一次 World Dijkstra。

群落级一次计算：
Hazard = IntenseHeat
Refuge = CAVE_X
SharedRoute = A -> R1 -> R2 -> CAVE_X

参与撤离的个体共享路线。
个体只保存：
- TravelPurpose
- Route identity/cache reference
- CurrentRouteIndex
- 必要的个体 departure offset。


21.2 禁止军队式同步
-------------------

共享路线不等于同步轨迹。

DepartureDelay / IndividualUrgency 可受：
- Nerve；
- RoostAffinity；
- 当前距离出口；
- Bond partner；
- Injury；
- 当前 activity；
影响。

必须避免：
- 整群同一帧转向；
- 同一帧进入 shortcut；
- 完全相同 localGoal；
- 规则队列式移动。


============================================================
22. SocialBond 在旅行中的作用
============================================================

SocialBond 只提供有限社会粘性。

允许：
- 强 Bond 的一方稍等另一方；
- 两者更容易属于相近出发批次；
- 永久迁徙目标中，Bond partner 所在 Colony 提供轻微 destination bonus；
- 回迁时 FormerColony + Bond partner 可以共同提高吸引力。

禁止：
- 为 Bond partner 冲回已经致命的 DangerType；
- 跨房实时读取 partner 坐标形成心灵感应；
- A 等 B，B 等 A 造成无限 deadlock；
- 链式把整个群落强行拉走。


============================================================
23. Return Home / 天气结束后的返巢
============================================================

Emergency Refuge 天气结束后：
- Refuge 个体仍属于原 Home Colony；
- 不瞬移回家；
- 通过 ReturnHome TravelPurpose 重新规划安全路线；
- 分批返回；
- 玩家在中间房间时可以真实观察到返巢。

天气刚结束时不要所有个体同时离开 Refuge。
可以使用 ReturnWindow / stagger。

如果返回途中危险再次恶化：
- Cancel ReturnHome；
- 从当前位置重新评估最近 Refuge / Home；
- 不机械沿原路线倒车。


============================================================
24. 什么时候 Replan
============================================================

路线选定后要有 RouteCommitment，防止频繁抖动。

只有以下情况才应重规划：
1) NextRoom / connection 变得不可用；
2) 当前 Refuge 不再安全；
3) 当前路线出现高致命天气暴露；
4) 原版房内导航长时间无法接近出口，确认实际卡死；
5) 天气状态发生重大变化；
6) 更优目标明显优于当前目标超过 switching margin；
7) 当前目的本身失效（例如已经不需要 Refuge）。

禁止：
Refuge A 0.81 / B 0.82 -> 每秒 A/B 来回切。

建议新目标只有明显更优（例如 +0.10~0.20 量级）才切换，具体阈值实机调参。


============================================================
25. 天气连续性与压力衰减
============================================================

EnvironmentalPressure 不应每天重置。

概念：
newPressure = oldPressure * memoryRetention + currentCycleExposure

memoryRetention 建议量级 0.75~0.90，实际调参。

连续多个 Cycle 的坏天气应有有限连续性加权：
- 第 1 个 bad cycle：x1.0
- 连续第 2：约 x1.1~1.2
- 连续第 3：约 x1.2~1.35
- 设置上限，例如不超过约 x1.5

目标：
“偶发沙漠天气”是正常生活；
“连续多日异常”才改变长期生态。

不同压力衰减速度可以不同：
- Environment：相对快；
- Predator：中等；
- Mortality / ShelterFailure：相对慢。

不得让危险一结束第二天就完全忘记。


============================================================
26. 避免同一事件重复处罚
============================================================

例如 IntenseHeat 导致 3 只死亡：

合理：
- EnvironmentalPressure：记录环境本身长期恶劣；
- MortalityPressure：记录真实死亡；

禁止：
- IntenseHeat +0.4
- 死亡 +0.4
- “天气造成死亡”再额外 +0.4
三重重复。

三类压力表示不同信息：
Environmental = 地方本身长期难住
Mortality = 最近实际死很多同类
Predator = 捕食者长期占据

最终 MigrationPressure 可组合，但每项必须 clamp / 权重受控。


============================================================
27. 不允许自动偷看未来随机天气
============================================================

永久迁徙目的地评分不能读取未来多个 Cycle 的 RNG schedule，然后选择“后台知道未来更安全”的房间。

允许的信息：
- 已经历的天气历史；
- 当前/即将发生天气，仅用于当前旅行和短期避难；
- 房间稳定环境属性；
- 已知 Shelter / Refuge 经验。

Desert Batfly 不应拥有系统后台全知能力。


============================================================
28. Abstract / Realized 分层
============================================================

28.1 永久迁徙
-------------

如果个体未 realized：
- 优先使用 AbstractCreature / AbstractCreatureAI / WorldCoordinate 完成跨房迁移；
- 不要求游戏持续 realize 其经过的每个房间。

如果玩家恰好进入迁徙路线并使个体 realize：
- 当前 TravelIntent / route 能续接到 realized FlyAI；
- 玩家可抓、杀、干扰它；
- 之后再 abstractize 时继续保留有效目的。


28.2 Emergency Refuge
---------------------

如果相关房间正在 realized，应该尽量真实表现：
- 离巢；
- 进入出口；
- 跨 room；
- 到达 Refuge；
- 后续回巢。

如果全部未 realized，可使用 abstract travel 模拟，但不得改变 Home Colony 归属。


============================================================
29. 持久化要求
============================================================

必须持久化/可恢复：
- Colony population ownership / 必要群落状态；
- 个体 CurrentColony；
- 个体 LastMigrationCycle；
- PreviousColony（若实现）；
- Colony long-term pressures；
- Migration cooldown；
- 必要的 KnownRefuge / ShelterFailure 轻量信息。

不建议持久化：
- 每帧 route local target；
- 房内 tile path；
- runtime velocity；
- 短期 TravelSuspendedByThreat。

Save schema 必须：
- 对旧存档向后兼容；
- 缺字段使用安全默认值；
- clamp 0..1；
- 防 NaN / Infinity；
- 不丢 unrecognizedSaveStrings；
- 不破坏 Task 04 / 05A 现有数据。


============================================================
30. 推荐代码职责拆分
============================================================

具体文件名可按 main 调整，但不要把全部逻辑塞进 DesertBatflyAI.cs。

建议职责：

DesertBatflyColonyState.cs
- Colony persistent state
- population floors/caps
- long-term pressures

DesertBatflyColonyMigration.cs
- migration pressure
- batch selection
- destination selection
- migration cooldown

DesertBatflyWeatherEcology.cs
- Task 07/09 与统一 Weather Ecology sample 的桥接
- ShelterFailure / actual exposure 汇总

DesertBatflyRefuge.cs
- Hive Shelter Quality
- Refuge candidate / refuge target
- KnownRefuge

DesertBatflyTravelNavigation.cs
- TravelIntent
- route state
- world graph planner interface
- room transition continuation

DesertBatflyPopulationRecovery.cs
- HardMinimumPersistence
- NaturalRecoveryCeiling
- Cycle background recovery

如果现有 World/Weather 层已有更合适的通用 manager，应复用，不要重复建立全局单例。


============================================================
31. 性能预算
============================================================

硬要求：
- 不每帧扫描整个区域；
- 不每只蝠蝇独立频繁跑 world Dijkstra；
- 不构建 N×N 社会关系；
- 不构建跨多个 room 的 tile-level A*；
- 不为了天气压力每帧遍历所有 AbstractCreature。

建议：
- Weather exposure 低频累计 / event-based；
- Colony pressures 在 Cycle/固定低频点更新；
- World route 按 Colony + Purpose + Hazard 缓存；
- 个体只消费共享路线；
- Refuge candidate 先 room-level 粗筛，Top N 再做局部安全验证；
- 目标/路线状态不变时不重算。


============================================================
32. Debug / Observatory 必须可观察
============================================================

Task 09 很难只靠“看起来差不多”验收，必须提供可调试信息。

建议在现有 AI Debugger / trace 中暴露：

Colony：
- Home Colony
- Population / Preferred / SoftCapacity
- HardMinimumPersistence
- NaturalRecoveryCeiling
- MortalityPressure
- PredatorPressure
- EnvironmentalPressure
- ShelterFailureMemory
- MigrationPressure
- MigrationCooldown

Weather Refuge：
- Current hazard
- HomeShelterQuality
- RegionalWeatherStress
- RelativeHabitatStress
- Selected Refuge
- RefugeScore
- EstimatedTravelTime
- TimeUntilDanger

Travel：
- TravelPurpose
- DestinationRoom
- Route rooms
- RouteIndex
- NextRoom
- Suspended / Replanning reason

个体迁徙：
- migration propensity
- selected/not selected reason
- CurrentColony / PreviousColony
- LastMigrationCycle

禁止为了 Debug 改变随机消费顺序或 AI 行为。


============================================================
33. 自动测试要求
============================================================

至少建立可在 tests/DesertBatfly 中运行的纯逻辑测试，覆盖：

A. Pressure / hysteresis
- 单次小事件不迁徙；
- 连续死亡/捕食逐渐升压；
- begin/continue/stop 阈值无抖动；
- pressure 正常衰减且 clamp。

B. Regional vs Relative
- A/B/C 同样危险时，不产生天气驱动互迁；
- 只有 A 明显更差时，A 才产生较强 relative migration drive。

C. Population recovery
- 高压力仍允许最低恢复；
- 不超过当前 NaturalRecoveryCeiling；
- 单 Cycle 不瞬间补满；
- SoftCapacity 不被误当硬上限。

D. Batch selection
- 不迁空 Colony；
- 严重 injury 个体迁出概率明显降低；
- RoostAffinity / SocialBond 有有限影响；
- 无 SocialRole 依赖。

E. Destination selection
- 同区域 DESERTSWARMROOM 才能成为永久迁徙目标；
- 更安全但略远的 Colony 可优于近但危险 Colony；
- 不读取未来天气 RNG。

F. Route planner
- 最短但致命路线输给稍长安全路线；
- route unreachable 时正确失败；
- switch margin 防止 A/B 抖动；
- Emergency/Return/Migration 使用不同权重但共享 planner。

G. Refuge
- Home shelter 足够 -> 不撤离；
- Home 不足 + 有安全可达 Refuge -> 撤离；
- Refuge 安全但路线致命 -> 不选择；
- 来不及到达 -> 留在 local shelter；
- 天气结束 -> ReturnHome；
- Refuge 不改变 Home Colony population ownership。

H. Identity persistence
- 迁徙前后 EntityID / Personality / Sex / Bond / Injury / Trauma 不变化；
- old save 缺 Task 09 字段能安全加载。

34. 实机验收场景
============================================================

必须准备至少以下手工场景：

Scenario 1：普通群落稳定
- 无 Peach；
- 偶发普通天气；
- 多 Cycle 无明显迁徙；
- 背景恢复缓慢正常。

Scenario 2：Peach 长期捕食
- Peach 连续多个 Cycle 驻留/捕食；
- MigrationPressure 缓慢升高；
- 小批次个体迁往更合适 Colony；
- 原 Colony 不瞬间补满。

Scenario 3：单次 HeatWave
- 群落回巢/躲避；
- 不永久迁徙。

Scenario 4：连续 HeatWave
- EnvironmentalPressure 累积；
- RecoveryCeiling 降低；
- 若 Home shelter 足够，ShelterFailure 很低；
- 若 Home shelter 反复不足，长期迁徙概率升高。

Scenario 5：区域级 IntenseHeat
- 所有 DESERTSWARMROOM 都危险；
- 不出现 A->B->C->A 乱迁；
- Home shelter 足够的群落留巢；
- shelter 不足的群落提前去 Refuge；
- 天气结束返回。

Scenario 6：Refuge 路线选择
- 短路线穿致命房；
- 长路线安全；
- 选择长路线。

Scenario 7：中途遇 Predator
- Travel 暂停；
- Escape；
- 威胁解除后继续 route。

Scenario 8：严重 Wing Injury
- 伤者不盲目长途撤离；
- 选择近 Refuge 或 local shelter；
- 不破坏 Task 04 recovery。

Scenario 9：回迁
- A 恶化，个体 A->B；
- 若干 Cycle 后 B 恶化、A 恢复；
- 部分旧居民允许 B->A；
- 不发生每 Cycle 往返抖动。

Scenario 10：多个 Colony 共用 Refuge
- A/B 群落灾前分批进入同一个安全洞穴；
- 不合并 Home Colony；
- 灾后分别返回各自 Home。

38. 完成定义 / Definition of Done
============================================================

Task 09 只有同时满足以下条件才算完成：

1) DESERTSWARMROOM 具有跨 Cycle 群落状态；
2) 高死亡、长期捕食、反复 shelter failure 能形成可解释的迁徙压力；
3) 单次天气不直接导致永久搬家；
4) 区域级 DangerType 主要通过 Temporary Refuge 处理，而不是群落间乱迁；
5) Home Hive shelter 足够时会优先留巢；
6) Home 不安全且存在可达 Refuge 时会提前撤离；
7) Refuge 天气结束后能回 Home；
8) 世界图路线能避开明显致命中转房；
9) 房内移动继续复用原版 FlyAI / native pathing，不出现新的机械直线控制；
10) 永久迁徙是小批次真实个体迁徙；
11) 迁徙后允许未来自然回迁，但有 cooldown / hysteresis 防抖；
12) 即使环境长期恶劣，群落仍保留最低限度背景恢复；
13) 背景恢复慢且受 ceiling 限制，不会瞬间补满；
14) EntityID / Personality / Sex / Bond / Trauma / Injury 在迁徙前后保持；
15) 多 Colony 可以临时共用 Refuge 而不合并；
16) 伤病、即时危险、SocialBond 与 Travel priority 正确；
17) 无 SocialRole 回归；
18) 无每帧区域级昂贵扫描；
19) Debug 能解释“为什么迁、为什么不迁、为什么选这个 Refuge/route”；
20) 自动测试与实机场景均通过。

39. 最终行为目标
============================================================

玩家不应该看到一个后台人口表，而应该从世界行为中自然读出生态变化：

- Peach 长期守着某个蝠蝇房，那个群落会慢慢衰退；
- 一些幸存蝠蝇会真正搬去附近更安全的群落；
- 原巢不会立刻刷满，但即使长期恶劣也不会轻易永久死区；
- 连续灾害到来前，蝠蝇会提前回巢；
- 本巢扛不住时，它们会沿真实房间连接前往安全洞穴；
- 玩家可能在中间房间看到一批逃难蝠蝇经过；
- 多个群落可能在大灾害时暂时挤进同一避难所；
- 天气结束后，它们会逐步返回自己的栖息地；
- 如果某个旧巢长期反复失效，而附近群落稳定，部分个体才真正永久迁走；
- 数个 Cycle 之后旧巢恢复，曾经离开的个体也可能自然回迁；
- 所有这些变化都来自同一个世界图、真实个体身份、天气历史和生态压力，而不是隐藏的瞬间传送或固定脚本。

这就是 Task 09 的目标：
让 Desert Batfly 的“群落”成为 Rain World 世界中会经历灾害、避难、衰退、恢复和重新分布的动态生态单位，同时保持原版飞行的自然感和可维护的性能预算。
