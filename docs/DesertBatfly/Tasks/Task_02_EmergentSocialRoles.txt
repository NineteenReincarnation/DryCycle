Desert Batfly Task 02
Emergent Social Roles / 稀疏涌现式社会角色
STATUS: REJECTED / 否决·已移除
====================================================

0. 本文件性质
-----------
本文件不再是可执行 Codex 任务书。

Task 02 已经过实现和实机观察，并于 2026-09-06 正式否决。
任何后续 Codex / Agent / 开发者都不得根据旧设计恢复 Sentinel、Bully、Opportunist 或类似的显性社会职业系统。

当前权威结论见：
- src/Creatures/DesertBatfly/DiscussionStatus.txt 第 2 项；
- docs/DesertBatfly-Emergent-Social-Roles.md。


1. 否决内容
-----------
以下机制从当前 Desert Batfly 设计中移除：
- Expressed Social Role 作为实际游戏状态；
- Sentinel / 哨戒者；
- Bully / 挑衅者；
- Opportunist / 机会主义者；
- Sentinel/Bully/Opportunist role score；
- role entry threshold；
- role dominance lead；
- RoleCommitment / RoleCooldown；
- soft role budget / 角色人口压力；
- Sentinel ThreatConfidence / role alarm；
- Opportunist opportunity/recovery-return；
- Bully 专属 Harass / Observe / FakeDive 参数修正；
- 任何 role-specific locomotion steering。


2. 主要否决原因
---------------

2.1 运动层副作用
~~~~~~~~~~~~~~~
旧实现为了让 Sentinel 位于群体外围，会根据 Flock.Center 计算外围目标，并在普通 Fly locomotion 运行时：
- 改写 FlyAI.localGoal；
- 额外修改 mainBodyChunk.vel；
- 持续尝试维持近似固定的外围半径。

实机观察出现部分蝠蝇沿近似竖直轴反复上下直线飞行的机械振荡。
该表现与 Rain World 原版蝠蝇自然、不稳定、带随机性的飞行观感冲突。

今后任何 Desert Batfly 社会/生态系统都不得建立第二套持续位置控制器去和 FlyAI 抢 locomotion 所有权。

2.2 设计抽象不合适
~~~~~~~~~~~~~~~~~
Desert Batfly 不需要被解释为具有“职业分工”的群居社会。

现有系统已经能产生连续而自然的个体差异：
- Temperament；
- Nerve；
- Conformity；
- RoostAffinity；
- SandSpitAffinity；
- VengeanceAffinity；
- Sex；
- SocialBond；
- Grief；
- Trauma / PTSD；
- GrabMemory；
- Thirst；
- Injury；
- Fear；
- Vengeance；
- Roost/Chain；
- 普通 Harass / Observe / FakeDive / Dive / Attach。

“更警觉”“更爱惹事”“危险后更早回来”如果未来仍然需要，应作为这些通用变量对普通决策权重的连续影响，而不是先分配一个 Role 再由 Role 改行为。

2.3 横向耦合成本过高
~~~~~~~~~~~~~~~~~~~
旧 Task 02 最终侵入：
- DesertBatflyAI；
- 普通 Flight；
- Creature scan；
- Injury；
- FlockSnapshot；
- AI Observatory；
- Debug Trace；
- 托管测试。

对一个生态点缀功能而言，控制面过宽，后续维护成本和回归风险不合理。


3. 当前迁移要求
---------------
当前代码迁移遵循两阶段：

A. 功能删除（必须立即成立）
- 所有 role score 永久为 0；
- role selector 永久返回 None；
- role modifier 全部中性；
- role visible scan 无行为；
- role ordinary-flight bias 无行为；
- 不允许角色代码写 localGoal；
- 不允许角色代码施加速度；
- FlockSnapshot 不再读取每只蝠蝇的 Role；
- 回归测试验证无法重新激活角色。

B. 结构清理（兼容层逐步移除）
旧的类型名可能暂时被 AI Observatory、Injury 或旧调用点引用。
在这些依赖完全迁移之前，允许保留最小“零行为兼容壳”。

兼容壳的硬规则：
- 不得计算真正的 role score；
- 不得保存 runtime role lifecycle；
- 不得修改行为；
- 不得修改移动；
- 不得触发警报；
- 不得改变攻击资格或 AttackSlots；
- 不得重新形成 soft budget；
- 必须明确标注 REJECTED FEATURE COMPATIBILITY。

最终结构目标是连兼容壳也删除，但删除兼容壳只是源码清洁工作，不得改变任何游戏行为。


4. 未来替代方向
---------------
未来如果继续丰富沙漠蝠蝇社会行为，优先采用：
- Personality 的连续权重；
- 真实可观察的 Social Signal；
- 局部事件传播；
- Conformity 对信号响应强弱的影响；
- SocialBond 对具体同伴事件的影响；
- Trauma / Grief / Injury 对行为的连续压制；
- ThreatStyleMemory 等经过单独讨论的有限经历记忆。

禁止把这些系统重新包装成 SentinelRole / BullyRole / OpportunistRole。


5. 验收标准
-----------
Task 02 的“完成”现在表示删除完成，而不是角色功能完成。

必须满足：
1) 10,000 个 Personality 测试中显性角色数量 = 0；
2) 任何旧 role constructor/score API 都不能生成非零 score；
3) Select(...) 永远返回 None；
4) Sentinel/Bully/Opportunist 不改变 Observe/Harass/FakeDive 参数；
5) 不存在 role-specific localGoal 写入；
6) 不存在 role-specific velocity steering；
7) FlockSnapshot 不扫描 Role；
8) SocialBond / Grief / Trauma / Vengeance / Injury / Roost 等非 Task 02 系统保持原有行为；
9) DiscussionStatus 第 2 项保持【否决·已移除】；
10) 后续开发不得从 Git 历史或旧任务书自动恢复该设计。
