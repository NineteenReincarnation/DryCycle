======================================================================
0. 文档定位
======================================================================

本清单只定义“当前文件的真实职责、目标领域和迁移意图”。

它不是一次性 rename 脚本，也不要求 R0 立即移动任何生产文件。

迁移原则：

1. 先替换架构连接，再移动文件；
2. 先建立正式 API，再删除 Bridge；
3. 只有职责清楚后才决定是否拆文件；
4. DB_ 是源码类型/文件前缀，不改变外部 DesertBatfly ID；
5. Task09～Task13 只属于开发历史，不进入最终生产命名；
6. 一次迁移尽量只处理一个领域；
7. 每次 move/rename 前后都必须保持行为契约；
8. 本表中的 SPLIT / MERGE 是目标方向，不是机械行数拆分要求。

状态标记：

KEEP/RENAME
- 职责健康，主要做 DB_ rename / domain move。

SPLIT
- 当前文件包含多个独立职责，重构后按职责拆出。

MERGE/ABSORB
- 当前代码应并入新的正式 Runtime/Context/Event 服务。

DELETE AFTER REPLACEMENT
- 历史 Bridge/Detour/补丁层；正式 API 建好后删除。

EXTERNAL INTEGRATION
- 真正 Rain World / Watcher / Warp / Sandbox 边界，允许保留 Hook/Adapter/Compatibility 概念。

REVIEW
- 目标归属需要在对应阶段结合真实调用关系再定，不先为了目录整齐强制移动。
