Purpose
=======

This ledger exists because deleting a Bridge/Integration file is not itself a successful
refactor. Every behavior that mattered in the deleted file must have a live direct owner,
and the new call path must remain reachable after R1-R4 changed the update pipeline.

R5 uses two permanent guards:
- tests/DesertBatfly/Program.Task14R5Retention.cs — managed IL call-path/ordering guards.
- scripts/check-desertbatfly-r5-retention.sh — source/file/import ownership guards.

Live Rain World validation is still required later. These guards prove code-side reachability
and ownership, not final in-game tuning.

Deletion effect audit found two semantic drifts and corrected them in B5:
1. Anonymous Alarm escape threshold
   - old ThreatBridge: anonymous hazard required response >= 0.34.
   - first B4 direct implementation accidentally used the ordinary >= 0.30 threshold.
   - B5 restores explicit 0.30 concrete / 0.34 anonymous thresholds.
2. Capture event ordering
   - before B4, DB_EventConsumers handled Intimidation first and SignalIntegration published
     capture Distress/Alarm afterward because of DB_EventHub subscription order.
   - first B4 direct fold published Distress/Alarm before Intimidation, which could let the
     same event's DistressInterest alter initial Vengeance candidate scoring.
   - B5 restores direct-experience/Intimidation commit first, social signal publication second.

B5 — RuntimePatch classification
======================================================================

DesertBatflyRuntimePatch.cs [RETAIN]
Classification: integration-only infrastructure, NOT an internal behavior bridge.

Exact production reflection whitelist under src/Creatures/DesertBatfly:
1. DesertBatflyRuntimePatch.cs
   - generic optional Harmony reflection helper.
2. DesertBatflySandbox.cs
   - patches CreatureSymbol sprite/color for DesertBatfly sandbox representation.
3. DesertBatflyWarpCompatibility.cs
   - optional Warp 1.9.x RoomInfo/category compatibility without a hard dependency.

Why deletion would be wrong:
- deleting RuntimePatch would lose Sandbox symbol support and Warp compatibility.
- neither consumer owns AI, travel, environment, social, signal, threat or locomotion logic.
- Hooks explicitly enables/disables both integration surfaces at lifecycle boundaries.

Final code-side repository audit:
- *Bridge.cs under DesertBatfly: 0.
- MonoMod.RuntimeDetour imports under DesertBatfly: 0.
- System.Reflection files under DesertBatfly: exactly the three integration files above.
- RuntimePatch production users: exactly RuntimePatch itself + Sandbox + WarpCompatibility.
