0. 文档目的
======================================================================

本文件不是新的玩法设计。

它记录 Task14 R0 开始时的“不可误伤基线”，用于后续 R1～R7 判断：

- 某个失败到底是批准行为发生回归；
- 还是旧 Bridge / Hook / Reflection 架构被有意替换；
- 某个字符串是否属于必须保持的外部身份；
- 某个测试是否应该继续保留；
- 某个已知风险在哪个阶段关闭。

R0 原则：

1. 不搬动大文件；
2. 不批量 DB_ rename；
3. 不删除旧 Bridge；
4. 不借基线阶段改玩法；
5. 先保护外部身份和行为契约；
6. 将“Architecture Lock”与“Behavior Contract”分离；
7. 已知 Bug 不通过测试锁成正确行为。

2. 必须保持的外部稳定身份
======================================================================

以下字符串属于游戏、存档、world authoring 或已存在外部兼容层可见身份。

DB_ 源码重命名不得修改它们。

2.1 CreatureTemplate.Type
--------------------

    DesertBatfly

来源：DesertBatflyDefinition.CreatureType

后续源码类型可以变为 DB_Definition / DB_Creature，
但 CreatureTemplate.Type.value 必须继续为 "DesertBatfly"。

2.2 Sandbox unlock
--------------------

    DesertBatfly

来源：DesertBatflySandbox.UnlockValue

它与 CreatureTemplate.Type 同值，依赖 Rain World 原生 sandbox 映射。
不得改为 DB_Creature / DB_DesertBatfly 等新值。

2.3 主 CreatureState save key
--------------------

    DCDesertBatflyV1

来源：DesertBatflyState.SaveKey

这是现有个体状态主 payload 的 versioned key。
重构内部 DB_State 不得改变该 key。

2.4 Threat Signature save key
--------------------

    DCDesertBatflyThreatV1

来源：DesertBatflyThreatMemoryStore.SaveKey

Threat Signature 继续使用独立扩展 key；
不得为了“统一命名”并入主 payload 或改成 DB_ThreatV1。

2.5 Colony ledger save prefix
--------------------

    DCBATCOLONY09<svB>

Payload version:

    V1

来源：DesertBatflyColonyRuntime.SavePrefix / PayloadVersion

注意：
这里的 "09" 是已经存在于存档数据中的历史版本身份。
即使 Task09 命名从生产运行时代码退出，该字符串也必须继续保留以读取旧存档。

这是“开发 Task 编号退出源码，但外部兼容字符串保留”的明确例外。

2.6 World room tag
--------------------

    DESERTSWARMROOM

来源：DesertSwarmRoom.IsDesertSwarmRoom

world.txt / room tag authoring 继续依赖该值。
不得因为类重命名为 DB_* 而修改。

3. 持久状态 schema 基线
======================================================================

3.1 主 State
--------------------

当前 DesertBatflyState 继续继承 HealthState。
主保存 key：DCDesertBatflyV1。

R0 已有测试保护：

- locale-independent round trip；
- Thirst / Cooldown / Bites；
- MealConsumed / InHive / health；
- GrabMemory；
- PlayerTrauma；
- PredatorTrauma；
- SocialBond full EntityID；
- Grief；
- malformed payload sanitization；
- legacy payload optional-field reset；
- foreign unrecognizedSaveStrings preservation。

Task14 默认不引入主存档 schema 迁移。
如后续确有必要新增字段，应优先继续使用版本化扩展 key，而不是破坏旧 indices。

3.2 Threat memory
--------------------

Threat Signature 使用独立：

    DCDesertBatflyThreatV1

不得让 Current Threat Cue / Acute Event state 进入 persistent State。

3.3 Colony ledger
--------------------

Colony / individual ecology 使用独立 SaveState ledger：

    DCBATCOLONY09<svB> + V1 payload

Task14 必须保持：

- CurrentColony；
- PreviousColony；
- PendingMigrationColony；
- LastMigrationCycle；
- colony pressure / population continuity；
- legacy/short payload safe defaults。

4. Behavior Contract vs Architecture Lock
======================================================================

R0 后测试分成两类。

A. Behavior Contract
--------------------

这类测试描述已经批准的玩法、数据语义、边界和不允许发生的副作用。

重构后必须继续成立；只有用户明确重新设计玩法才能修改。

主要包括：

Program.cs
- Personality deterministic stream；
- Sex 48/52 target distribution；
- true avenger calibration；
- SandSpit trait；
- save round trip / malformed guard；
- SocialBond single-slot / asymmetry / grief；
- Rock non-finishing rule；
- Peach remains edible rules；
- AttackSlots cap；
- Emergence terrain legality。

Program.RejectedTask02.cs
- Sentinel / Bully / Opportunist runtime physically absent；
- Role API 不得复活。

Program.Task09.cs
- colony pressure / hysteresis；
- regional-relative stress；
- recovery floor/ceiling；
- migration batch / cooldown；
- injury gating；
- route cost / route commitment / replan；
- refuge timing；
- persistence compatibility。

Program.Task10.cs / Program.Task10Guards.cs
- Neutral Social Life 行为语义；
- realized-only transient state；
- no combat / trauma ownership；
- bounded room cache；
- no second BodyChunk velocity locomotion。

Program.Task11.cs / EventSemantics
- 12-dimensional Threat Signature；
- four-player isolation；
- evidence mapping；
- decay / confidence；
- no input cheating；
- current cue non-persistent；
- event semantics。

Program.Task12.cs
- exactly six signals；
- packet cap / hop cap / generation history；
- visual vs acoustic semantics；
- no persistent signal state；
- no direct locomotion ownership。

Program.Task13.cs / Program.Task13Rain.cs
- exactly six environmental phases；
- DryCycle-only weather authority；
- RoomSettings Fog does not activate ecology；
- Fog/DenseFog visibility semantics；
- HeavyRain non-Acute rule；
- DeathRain hard survival；
- no Task13 cross-room ownership；
- no ordinary BodyChunk.vel weather locomotion。

B. Architecture Lock
--------------------

这类测试/断言只描述“当前为了接线而存在的实现形状”。
它们不能成为 Task14 的长期行为契约。

典型包括：

- xxxBridge 类型必须存在；
- xxxHook 私有方法必须存在；
- MethodCallOffset 强制 Task11 -> Task12 -> Task13 -> Task10；
- MarkTravelOwnedFrame 必须被调用；
- private Reflection method 必须可被找到；
- DynamicMethod / RuntimeDetour 本身作为成功条件。

主要分布：

- Program.Task11Final.cs；
- Program.Task12.cs 中 Bridge lifecycle / pipeline shape 部分；
- Program.Task13.cs 中 Integration/Bridge shape 部分；
- 其他通过私有方法名判断实现顺序的 assertion。

处理原则：

1. R0～R4 可以暂时保留这些测试，帮助迁移期间确认旧 adapter 尚可工作；
2. 一旦对应新 Runtime/Event/Arbiter API 成为 authority，必须先补新的 Behavior/Architecture Contract；
3. 然后删除对应 Architecture Lock；
4. 不得为了让旧测试继续通过而保留已经无意义的 Bridge 壳。

6. Known hidden-risk register
======================================================================

HB-01 — Severe Injury Hive Dijkstra seed / second flight loop
状态：【OPEN】
目标阶段：R4

当前风险：
- TryDriveRecoveryHive 使用 body position 调 ProgressLocalGoalAlongDijkstraMap；
- 同时直接 Lerp mainBodyChunk.vel；
- 可能形成短步抖动 / 与 native FlyAI 普通飞行竞争。

R0 只冻结“必须继续使用 native Dijkstra”这一行为契约，
不把错误参数和第二 velocity loop 当正确行为锁住。

HB-02 — realized Travel same-frame partial guard
状态：【OPEN】
目标阶段：R3（如基础 Runtime 提前建立，也可更早关闭）

当前风险：
- TickRoomProgressRealized 有 LastObservedFrame guard；
- TickCooldownRealized 和 DepartureDelay-- 位于该 guard 之前；
- FleeFromRainUpdate 与 UpdateAI 都可能进入 TryDriveRealized。

要求最终：
- realized Travel tick 整体 exactly-once/frame；
- DepartureDelay / ReplanCooldown / SameRoomTravelTicks 都最多推进一次。

HB-03 — Death attribution split
状态：【OPEN】
目标阶段：R1

当前来源：
- DB Creature/Intimidation recent lethal attribution；
- Threat Runtime Creature.Die attribution；
- Core Hooks grabbedBy -> likelyPredator -> Colony ReportDeath。

最终由 unified MortalityEvent 统一。

HB-04 — Peach tongue multi-hook semantic duplication
状态：【OPEN】
目标阶段：R1

Core Hooks / Watcher predation / Signal integration 都可观察 tongue transition。
最终只允许一个 CaptureEvent root。

HB-05 — CorpseWarning lifecycle
状态：【OPEN】
目标阶段：R1

Reset/Disable 缺少集中销毁已经加入 Room 的 transient warning owner。

HB-06 — Environment temporary Thirst mutation
状态：【OPEN】
目标阶段：R5

Heat/Harass 动机不得再通过临时修改 persistent Thirst 传参。

HB-07 — duplicate weapon perception
状态：【OPEN】
目标阶段：R2

旧 AI ScanWeapons / Threat room cache / DenseFog fallback 需要统一 observation。

HB-08 — eager Room runtime
状态：【OPEN】
目标阶段：R2

无 Desert Batfly 的普通 realized Room 不应自动建立完整 shelter/environment cache。

HB-09 — duplicated Signal visibility ranges
状态：【OPEN】
目标阶段：R2/R5

SignalDefinition 应成为唯一 Visual/Acoustic range authority。

HB-10 — Observatory ControlOwner is heuristic
状态：【OPEN】
目标阶段：R3

最终必须读取 Arbiter 真正的 PrimaryOwner / rejected proposals。
