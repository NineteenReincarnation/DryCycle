2.5 Travel 第一阶段进入真实 arbitration
--------------------------------------

DesertBatflyTravelNavigation 新增：

CanOwnRealizedFrame(DesertBatfly, out string)

该 API：

- 只查询；
- 不减少 DepartureDelay；
- 不 Replan；
- 不 LeaveRoom；
- 不改变 Suspended；
- current restraint / ImmediateDanger / severe Injury 会使 Travel proposal 失去资格；
- 历史 Suspended 本身不是永久 veto，阻塞解除后可重新被 Arbiter 选中。

UpdateAI 当前流程已经改成：

FrameContext
    ↓
BehaviorArbiter.ResolveFrame
    ↓
PrimaryOwner == Travel ?
    ├─ YES -> TryDriveRealized
    │           ├─ 成功：Travel 真正拥有该帧
    │           └─ 失败：同帧排除 Travel 后重新 resolve
    └─ NO  -> 进入仍待迁移的旧 executor pipeline

这比旧逻辑：

TryDriveRealized -> true -> 再打 TravelFrameStamp

前进了一层：Travel 现在先获得中央 owner，再执行。

Rain/FleeFromRain 嵌套回调不再第二次执行 Travel。若 Arbiter 判定 Travel，应由外层 UpdateAI 统一执行一次。
