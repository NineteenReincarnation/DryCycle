1. Current production architecture baseline
======================================================================

R6 has migrated the historical Desert Batfly implementation toward domain ownership without intentionally redesigning gameplay.

Current source-level invariants established so far:
- production Desert Batfly `.cs` files live under domain directories rather than the creature root;
- production Desert Batfly filenames use `DB_` domain identities;
- internal `DesertBatflyXxx` type declarations have been retired;
- production Task-number development terminology has exited runtime source;
- old `Behavior/ThreatSignature` physical ownership has been retired in favor of the Threat domain;
- internal Bridge/RuntimeDetour debt remains retired except explicit Sandbox/Warp compatibility reflection/patch integration;
- managed Desert Batfly tests use domain suites and current positive reflection targets.

3. B44 — Fear / Vengeance responsibility extraction
======================================================================

The remaining responsibility debt was that the real Extreme Vengeance state machine still lived in a `partial DB_FearRuntime` while `DB_VengeanceRuntime` acted as a façade.

Current design:
- `DB_FearRuntime` retains exactly one per-bat `ConditionalWeakTable<DB_Creature, State>` host;
- Fear host State embeds exactly one `DB_VengeanceRuntime.State`;
- `DB_VengeanceRuntime` owns no second weak table;
- Reset, Forget, death handling, trauma collapse and fear collapse therefore retain one synchronous object lifecycle;
- `DB_VengeanceRuntime` owns Mode, Participation, group arming, target/leader/supporter state, state-machine transitions, rescue/contact behavior, cancellation and owner-gated movement;
- ordinary Vengeance movement remains behind Arbiter ownership and `DB_FlightMotor`;
- Fear exposes only narrow host/fear/trauma services needed by Vengeance.

Behavior-preservation checks during B44 froze:
- Fear/Vengeance tuning constant values;
- critical Rally, Violence, grasp/tongue rescue, FlightMotor, Threat tactic, trauma and threat-notification call counts;
- switch/case state-machine structure;
- runtime string payloads.

B44 candidate and clean-promotion verification passed before entering the final working branch.

4. B45 — architecture consolidation checkpoint
======================================================================

B45 is a checkpoint, not R6 closure.

Its purpose is to consolidate and permanently guard the architecture already established while leaving the phase open for later project arrangements.

B45 introduces:
- a current `Program.ArchitectureDomainMigration` regression that verifies present formal owners, Integration lifecycle and Observatory enrichment order;

- refreshed progress/status documentation that explicitly keeps R6 open.

The aggregate guard protects:
- R5 retained bridge boundaries;
- R6 source-retention boundaries;
- Task-era terminology exit in production and managed Desert Batfly tests;
- DB_ production filenames/internal identities;
- absence of root-level Desert Batfly production C# and retired ThreatSignature directory;
- formal production owner presence;
- validity of positive managed reflection targets;
- Fear/Vengeance single-host ownership;
- published/save/world compatibility literals;
- Roslyn syntax parsing of Desert Batfly production and managed tests.
