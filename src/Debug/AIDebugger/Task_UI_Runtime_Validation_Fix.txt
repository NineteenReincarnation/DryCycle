============================================================
1. 总体目标
============================================================

完成后必须满足：

- Rain World 启动后 AI Observatory Host 明确安装成功。
- F7 能稳定打开/关闭 UI。
- 日志能够完整说明 Install -> Host -> F7 -> Backend -> DrawData -> Mesh -> Render 的每一步。
- ImGui 窗口真实显示在 Rain World 最终画面上。
- Input Gate 不再抛 MissingMethodException。
- Input Gate 即使失败，也只能降级输入隔离，不能阻止 UI 显示。
- 修复不得破坏现有 Pause/Step、Timeline、DockSpace、Session Export。
- 修复过程不得通过盲改大量 backend 参数来“碰运气”。

============================================================
2. 第一阶段：先完成诊断闭环，不先改渲染实现
============================================================

必须使用当前已经加入的启动/F7诊断日志，并继续补齐 Render 链日志。

需要确认并记录以下阶段：

[Install]
- AIDebuggerRuntime.Install requested
- Host object created
- Overlay camera created
- Host Bind completed

[Runtime]
- Host Update first tick
- F7 detected
- visible old -> new
- overlayCamera.enabled old -> new

[Backend]
- backend initialization started
- ImGui context created
- Docking flags configured
- font atlas built
- shader selected
- mesh created
- backend initialization completed

[Frame]
只记录首次成功帧与异常帧，不允许每帧刷日志：
- BeginFrame entered
- Window.Draw entered
- ImGui.Render completed
- DrawData.CmdListsCount
- DrawData.TotalVtxCount
- DrawData.TotalIdxCount

[Mesh]
- generated vertex count
- generated submesh count
- valid clip command count

[Render]
- OnPostRender reached
- overlay camera name/id
- screen width/height
- command buffer draw count
- Graphics.ExecuteCommandBuffer completed

所有“首次成功”日志只打印一次。
禁止产生每帧垃圾日志。

============================================================
3. F7 路径验收
============================================================

必须先证明 F7 是否真的进入 AIDebuggerHost.Update。

测试时预期出现：

DryCycle AI Observatory host Update is running.
DryCycle AI Observatory F7 detected.
DryCycle AI Observatory visibility toggled by F7. visibleNow=True

如果没有 F7 detected：

检查顺序：
1. Host Update 是否运行。
2. UnityEngine.Input.GetKeyDown(KeyCode.F7) 是否在当前 Rain World 输入环境可用。
3. 是否有其他 Mod/输入层吞掉功能键。
4. 必要时增加第二个临时诊断键，仅用于验证 Unity Input，不作为最终快捷键。

禁止在尚未证明 F7 失败前改 Docking/Renderer。

============================================================
4. Input Gate MissingMethodException 修复
============================================================

当前实机日志明确报错：

System.MissingMethodException:
RWInput.PlayerInputLogic(int,int)

任务要求：

1. 不再假定反编译源码中的签名一定等于 PUBLIC/运行时暴露签名。
2. 在实际运行程序集上枚举 RWInput 的 PlayerInputLogic overload：
   - method name
   - static/instance
   - return type
   - parameter count
   - parameter types
3. 记录找到的真实 overload 到一次性日志。
4. 根据真实签名安装 RuntimeDetour。
5. 如果存在多个候选，必须按完整签名选择，不允许只按名字选择。
6. 如果完全不存在：
   - 输出清晰 Warning
   - Input Gate 自动禁用
   - UI 继续正常运行
7. 禁止 Input Gate 安装失败导致 Observatory Install 失败。

验收：

日志不得再出现：
RWInput.PlayerInputLogic(int,int) MissingMethodException

并且 INTERACT 模式下玩家操作不会同时传给游戏。

============================================================
5. UI 不可见故障树
============================================================

当日志已经证明：
- F7 detected
- backend initialized

但画面仍无 UI 时，按以下顺序排查。

------------------------------------------------------------
5.1 ImGui 是否真的生成 DrawData
------------------------------------------------------------

检查：
- CmdListsCount > 0
- TotalVtxCount > 0
- TotalIdxCount > 0

情况 A：全部为 0
=> 问题在 Window/ImGui frame，不是 Unity renderer。

检查：
- Window.Draw 是否执行
- Compact/Full window 是否 Begin 成功
- alpha/opacity 是否为 0
- window pos/size 是否异常
- ini layout 是否把所有窗口保存到屏幕外

如果 ini/layout 可疑：
- 提供 Reset Layout
- 第一次测试强制使用已知屏内位置
- 不删除用户布局功能，只提供安全回退

情况 B：DrawData 正常
=> 继续 Renderer 排查。

------------------------------------------------------------
5.2 BuildMesh 是否正确
------------------------------------------------------------

确认：
- vertices.Count > 0
- drawCommands.Count > 0
- mesh.subMeshCount > 0
- 所有 index 均在 vertex range 内
- ClipRect 转换后不是全部被裁成 0 面积

需要记录首次可见帧：
- DisplayPos
- DisplaySize
- FramebufferScale
- 第一个有效 ClipRect
- 第一个顶点位置

重点检查 Y 轴方向与 clip rect 转换是否一致。

------------------------------------------------------------
5.3 Overlay Camera 是否真正渲染
------------------------------------------------------------

必须确认 OnPostRender 是否真实被调用。

若 OnPostRender 未执行：
- 不再继续调 Mesh/Shader
- 直接修 Camera 生命周期/渲染时序

检查：
- camera.enabled
- GameObject activeInHierarchy
- Camera depth
- Camera targetTexture
- camera.rect
- cullingMask=0 情况下 Unity 2020.3 是否仍走完整 render callbacks

如发现 cullingMask=0 导致该 Camera 不触发预期流程：
使用不会绘制世界对象但保证 Camera render callback 的安全方案。

禁止为了 UI 显示改变 Rain World 主 RoomCamera。

------------------------------------------------------------
5.4 CommandBuffer 是否执行
------------------------------------------------------------

如果 OnPostRender 已进入：

确认：
- commands.Clear 已执行
- SetViewport 使用真实屏幕大小
- SetViewProjectionMatrices 参数有效
- DrawMesh 调用次数 > 0
- ExecuteCommandBuffer 成功

增加首次帧诊断：
Render commands=N

如果 N=0：
返回 BuildMesh/clip 阶段。

------------------------------------------------------------
5.5 Shader 路径 A/B 测试
------------------------------------------------------------

当前优先 shader：
Futile/Basic
fallback:
Sprites/Default
UI/Default

不得直接假定 Futile/Basic 一定适合 ImGui Mesh。

如果：
- DrawData 正常
- Mesh 正常
- OnPostRender 正常
- DrawMesh commands > 0
- 画面仍不可见

则执行最小 A/B：

A. Futile/Basic
B. UI/Default 或 Sprites/Default

必须记录实际选择的 shader 名称。

同时确认：
- _MainTex
- vertex color
- alpha blending
- ZTest Always
- culling

如果 fallback shader 能显示而 Futile/Basic 不能：
正式 backend 不再优先使用 Futile/Basic。

------------------------------------------------------------
5.6 Projection / Coordinate 验证
------------------------------------------------------------

如果 shader 正常但仍不显示：

加入一个不依赖 ImGui DrawData 的临时诊断三角形/矩形，仅用于验证 backend projection。

要求：
- 固定屏幕坐标
- 固定不透明颜色
- 使用同一 Camera/CommandBuffer/Material

如果诊断矩形不可见：
=> Camera/projection/material pipeline 问题。

如果诊断矩形可见但 ImGui 不可见：
=> DrawData coordinate/clip/index 问题。

该诊断图形必须在修复完成后删除或放入 disabled diagnostic flag。

6. DockSpace / Layout 安全性
============================================================

当前已经修复：

本任务不得回退该修复。

============================================================
8. Backend Failure 降级策略
============================================================

任何 backend exception：

必须：
- LogError 完整异常
- visible=false
- overlay camera disabled
- backend disposed
- 不影响 DryCycle 其余系统

F7 再按时：
- 明确提示 backend 本 session 已失败
- 不重复制造 native assertion

Input Gate failure 与 Render Backend failure 必须是两个独立状态。

============================================================
9. cimgui.dll Loader 日志处理
============================================================

当前 BepInEx 会输出：

Skipping loading cimgui.dll because it's not a valid .NET assembly.

这属于 native DLL 位于 plugins 目录后被 Chainloader 扫描的结果。

本任务：

- 不把该 Debug 行当成 Observatory 错误。
- 验证 NativeBootstrap LoadLibrary 真实成功。
- 如有必要，在 Observatory 初始化日志打印：
  cimgui native preload success/failure
- 不因为该行把 cimgui.dll 删除。

只有出现 DllNotFoundException / EntryPointNotFoundException 时才视为 native runtime 故障。
