============================================================

</Reference>

Therefore the API assembly filename is verified as:
- rain-world-imgui-api.dll

The same discussion confirms consumer mods must reference the ImGui.NET.dll shipped by
RWImGUI itself rather than the official NuGet ImGui.NET package.

Verified registration usage from the public consumer example:

unsafe
{
    ImGUIAPI.AddMenuCallback(&MainImMenu.MenuCallback);
}

Verified callback shape:

public static void MenuCallback(
    ref nint idxgiSwapChain,
    ref uint syncInterval,
    ref uint flags)

Verified behavior responsibility split:
- consumer callback emits ImGui widgets
- RWImGUI owns the ImGui backend / Present integration
- consumer does not call ImGui.NewFrame()
- consumer does not call ImGui.Render()
- consumer does not own a Unity Camera renderer

============================================================
3. VERIFIED IMGUI.NET COMPATIBILITY CONSTRAINT
============================================================

A public user report reproduced this failure when the consumer mod deployed the ordinary
NuGet ImGui.NET 1.91.6.1 beside RWImGUI:

System.MissingMethodException:
void ImGuiNET.ImGuiNative.LoadFunctionPointers(...)

The user fixed it by removing the NuGet runtime DLL and referencing the ImGui.NET.dll
shipped with RWImGUI.

Rawra confirmed that RWImGUI uses a modified ImGui.NET fork for performance and support
for additional native ImGui libraries.

DryCycle migration rule:
- public NuGet ImGui.NET may temporarily remain compile-only for legacy source
- public NuGet ImGui.NET runtime must NOT be copied into Ancient Site plugins
- cimgui.dll from the retired DryCycle backend must NOT be copied there either
- the bridge compiles against RWImGUI's own ImGui.NET.dll with Private=false
