# Creature Core 开发进度

这个文件只记录 `src/Framework/Creature/Core` 里已经真正完成的工作。

记录时尽量说人话，不只写类名、接口名或内部实现细节。每完成一个 Core 任务，都要同步更新这里。

## 已完成

- 建好了生物 Core 框架目录，后续通用的生物核心轮子统一放在这里。
- 做好了生物注册说明书：可以登记一种生物是谁、属于哪个 Mod、显示名称叫什么，以及它在 `world.txt` 等地方还能用哪些别名识别。
- 做好了生物核心对象的创建登记：开发者可以分别告诉框架该怎么创建生物模板、状态、实际生物、抽象 AI 和实际 AI；不需要自定义的部分可以留空，继续走 Rain World 原版流程。
- 做好了注册信息冻结保护：一份生物说明书一旦正式交给注册系统，就不能再被偷偷修改，避免运行时登记信息前后不一致。
- 做好了生物别名管理：别名忽略大小写去重，保留第一次填写时的顺序，并且外部代码不能绕过接口直接修改。
- 做好了更简洁的注册写法：在保留完整 API 的同时，增加了 `Name`、`Alias`、`Aliases`、`Template`、`State`、`Realized`、`AbstractAI`、`AI` 这些短写法，功能不变，但注册代码更短、更容易读。
- 做好了统一的生物登记册：开发者把生物说明书交给 Registry 后，后面的 Rain World 核心 Hook 不需要每只生物自己重复写。
- 做好了注册冲突保护：两个生物如果用了相同的生物类型、类型编号、标准名称或别名，不会再看加载顺序互相覆盖，而是直接告诉开发者哪里撞了、是谁撞的。
- 做好了晚期注册保护：Rain World 一旦开始建立生物模板数组，就不再允许临时塞进新的生物类型，避免出现类型编号已经超出数组范围这种很难查的问题。
- 做好了生物模板接入：Registry 会在 Rain World 建立 StaticWorld 时调用各个生物登记好的模板创建方式，并检查返回的模板是不是对应的生物类型。
- 做好了模板失败回滚：如果一批自定义生物里后面的模板创建失败，前面已经临时写进 StaticWorld 的模板会还原，不会把游戏留在“只注册成功一半”的状态。
- 做好了原版流程回退：没有登记自定义 State、实际生物、抽象 AI 或实际 AI 的部分，会继续使用 Rain World 原版创建流程，不要求每只自定义生物把整套生命周期全部重写。
- 做好了自定义 State、实际生物、抽象 AI 和实际 AI 的统一创建转接，并给 Factory 抛出的异常补上生物类型和所属 Mod 信息，出错时更容易定位。
- 做好了抽象 AI 替换时的巢穴信息保留：Rain World 在默认 AbstractAI 上写入的出生巢穴位置不会因为换成自定义 AbstractAI 而丢掉。
- 做好了实际 AI 的重复创建保护：`InitiateAI` 被重复调用时，只要已有实际 AI，就不会再次调用开发者提供的 AI Factory。
- 做好了标准名称和别名的快速查询：Registry 会提前建立索引，不需要每次解析 `world.txt` 时把所有生物和所有别名重新遍历一遍。
