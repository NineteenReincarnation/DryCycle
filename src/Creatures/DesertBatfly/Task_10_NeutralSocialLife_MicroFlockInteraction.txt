Desert Batfly Task 10
Neutral Social Life + Micro-Flock Interaction
中性社会生活 + 微群体互动
Codex Execution Specification
============================================================

0. 任务性质
============================================================

这是 Desert Batfly 第 10 项正式可执行任务书。

本任务的核心目标不是“把蝠蝇飞得更平”，也不是删除原版 Fly 的拍翼、SwarmFlight 或自然高度变化，而是解决当前 Desert Batfly 在没有危险、没有攻击目标、没有迁徙、没有严重伤病、又没有成功进入 Roost 时，长期只剩下 Idle / Swarm / BatFlight 的问题。

当前观察到的体验问题是：
- 多只 Desert Batfly 在中性状态下会长时间各自悬空飞行；
- 原版 BatFlight 的拍翼节奏会自然产生上下升降；
- DESERTSWARMROOM 中当前 Hook 会使合适位置的 Desert Batfly 更频繁回到 FlyAI.Behavior.Swarm；
- 当没有其他行为打断时，大量个体会呈现“各自在空中上下飞”的背景粒子感；
- 单纯降低垂直速度只能掩盖症状，会损失原版 Fly 的自然飞行质感。

因此 Task 10 要建立一套“无事可做时也有生活”的中性社会行为层，使同一房间的 Desert Batfly 能够短暂结伴、擦身、追逐、组成松散微群、协商飞行位置、互相带动休息，并更自然地形成倒挂群。

【核心原则】
Task 10 不消灭正常的独自飞行。Solo Flight / Idle / Swarm 仍然是合法底层状态，但不能再成为大多数个体长期唯一的中性生活方式。

【绝对禁止】
本任务不是被否决的 Task 02 社会角色系统。
禁止重新引入或变相恢复：
- Sentinel
- Bully
- Opportunist
- Scout
- Leader
- Follower 作为永久职业
- Refuge Leader
- Migrator Role
- 任何持久化“职业/阶级/岗位”

本任务中的 TemporaryPartner、TemporaryAnchor、Chaser、Chased、Pair A/B 等都只能是短期互动中的临时关系，不能写入持久 State，不能成为 Personality 之外的新永久身份。

【必须】实现前重新读取 main 当前 DesertBatfly 代码。如果本任务书与后续 main 重构发生冲突，以“本任务书行为目标 + main 当前架构”共同决定具体实现，不允许机械恢复旧代码。

2. 最终体验目标
============================================================

玩家进入一个有较多 Desert Batfly 的 DESERTSWARMROOM 时，不应该长期只看到：

↑ ↓ ↑ ↓ ↑ ↓ ↑ ↓
↑ ↓ ↑ ↓ ↑ ↓ ↑ ↓

目标是出现不断变化、但不过度躁动的“群落日常”：

- 2 只短暂并行飞行；
- 2 只迎面后横向错开；
- 1 只活跃个体短时间追逐另一只；
- 3~6 只形成松散的横向微群；
- 两只过近时左右分流而不是一起向上避让；
- 一只准备倒挂时，附近同伴更愿意跟去休息；
- 已有倒挂链附近更容易继续形成小型聚集；
- 过一段时间互动自然结束，个体重新独飞；
- 危险、天气、伤病、迁徙等出现时，所有中性互动立即让路。

目标不是让 100% 个体一直互动。
建议实机调参目标：
- 任意时刻约 20%~50% 的健康、中性个体处于某种社会互动或向 Roost 过渡；
- 始终保留一部分 Solo Flight；
- 同一互动类型不应连续占据某只蝠蝇十几秒；
- 大群体不应同步进入同一种状态。


============================================================
3. 行为优先级
============================================================

Task 10 必须严格服从现有生存优先级。

建议总优先级：

1) 死亡 / 昏迷 / 被非 Fly 抓住 / shortcut / 强制 Passive
2) Immediate Danger / Escape / Peach / 玩家攻击 / 飞来的武器
3) Task 09 EmergencyRefuge / ReturnHome / ColonyMigration
4) Severe Injury / InjuryRecovery
5) 原版强制优先状态：Burrow / fleeFromRain / lure / SafariControl 等
6) 正在进行的正式攻击 / Retaliation / Attach / Interfere
7) 已经稳定进入的 Roost / Chain
8) Task 10 Neutral Social Interaction
9) 新的自发 Roost 决策
10) 原版 Idle / Swarm / Solo Flight fallback

注意：
- 已经挂好的蝠蝇不能为了“去社交”主动离开合法 Roost；
- 但 RoostInvitation / ChainSocialization 可以让仍在飞行的蝠蝇更愿意加入已有 Roost；
- Social Interaction 和“开始一个新 Roost”可以竞争，但一旦真正进入 Chain，Chain commitment 高于社会互动；
- 任何生存层事件发生时，社会状态必须可在当前帧或下一次 AI 更新安全取消。

4. Task 10 总体架构
============================================================

建议不要继续把全部逻辑塞进已经很大的 DesertBatflyAI.cs。

建议新增一个独立、可测试的中性社会控制器，例如：

src/Creatures/DesertBatfly/Social/
- DesertBatflySocialLife.cs
- DesertBatflySocialInteraction.cs（可选）
- DesertBatflyMicroFlock.cs（可选）

具体文件数量可根据 main 当前风格调整，但职责必须保持清晰：

DesertBatflyAI：
- 决定当前高层生存/攻击状态；
- 在满足 Neutral Eligibility 时让 SocialLife 获得一次决策机会；
- 提供现有 Steer / Roost / threat 等能力的安全入口。

DesertBatflySocialLife：
- SocialDrive；
- SocialCooldown；
- 当前短期互动类型；
- TemporaryPartner / TemporaryAnchor；
- InteractionTicks；
- 候选选择；
- 互动启动/更新/结束/取消；
- 与房间级邻居缓存/微群 registry 协作。

房间级轻量 Runtime：
- 缓存当前可社交 Desert Batfly；
- Pair / MicroFlock 的临时 reservation；
- 防止一只蝠蝇同时参加多个互动；
- 不持久化；
- Room unload 后自然释放。

禁止：
- 每只蝠蝇保存整个群体状态副本；
- 每帧每只扫描 room 中所有 Desert Batfly；
- 永久 leader；
- N×N 持久关系矩阵。


============================================================
5. Neutral Eligibility / 谁可以社交
============================================================

只有满足全部基础条件的个体才能发起新的中性互动：

- alive
- Consious
- room != null
- 不在 shortcut
- 不被非 Fly 抓住
- Emergence 不在强制出巢动画
- 当前没有 Immediate Danger
- retreat == 0 / 非 Escape
- Task 09 没有需要当前执行的 TravelIntent
- 非 severe injury / 非 InjuryRecovery
- 非正式攻击状态
- 非 Attach / Interfere / RetaliationCharge
- 非 fleeFromRain
- 非 Burrow
- 非 SafariControlled
- 当前不在稳定 Chain / Hang

候选 partner 还必须：
- 同一 room；
- 同 ripple side / 当前现有合法交互层；
- 距离在社会感知范围内；
- 必要时存在 VisualContact；
- 没有被其他 interaction reservation 占用；
- 没有进入自己的高优先级状态。

非常近距离的 PositionNegotiation 可以放宽 VisualContact，但不能穿墙感知。


============================================================
6. SocialDrive：让“长期无事”自然产生事件
============================================================

每个 realized Desert Batfly 增加一个非持久化 SocialDrive，范围 0..1。

SocialDrive 不写入 DesertBatflyState，不跨存档，不属于 Personality。

基本规则：

- 健康、中性、持续 Solo Flight 时缓慢上升；
- Idle / Swarm 长时间没有互动时继续上升；
- 完成一次中性互动后明显下降；
- 刚取消互动后下降一部分并进入 cooldown；
- 正在 Roost 时缓慢下降或冻结；
- Danger / Escape / Travel / Severe Injury / Attack 时冻结或快速压低；
- SocialDrive 高只代表“更愿意尝试互动”，不是强制一定成功；
- 没有合法同伴时即使 SocialDrive=1，也继续正常独飞。

建议初始量级：
- 连续 5~12 秒中性独飞后明显增加互动概率；
- 不使用每帧 Random.value 判定；
- 只在低频 social scan 时尝试启动互动。

SocialDrive 的增长速度可弱受 Personality 影响：
- Conformity 高：增长稍快；
- Temperament 极高：更偏向主动短互动；
- RoostAffinity 高：高 SocialDrive 时更容易转向 RoostInvitation / Roost；
- Conformity 很低：允许长时间 Solo Flight。

禁止让 SocialDrive 变成“饥饿条”式强制资源。


============================================================
7. SocialCooldown + 防重复机制
============================================================

每只蝠蝇完成或取消一个互动后进入 SocialCooldown。

建议量级：3~10 秒（120~400 ticks），按互动类型和 Personality 调整。

目的：
- 防止 SocialChase 连续触发；
- 防止同两只蝠蝇不断 Pair -> End -> Pair；
- 防止行为过碎；
- 保留 Solo Flight 呼吸时间。

建议额外保留：
- LastInteractionType（只保留一个，非持久）；
- LastPartnerID（短期，非持久）；
- RepetitionPenalty。

同一类型连续出现时降低权重；同一 partner 在很短时间内重复匹配时降低权重。

不要保存完整互动历史。


============================================================
8. 个体性格如何映射到社会行为
============================================================

必须复用当前已有 Personality，不新增 SocialRole。

8.1 Temperament
----------------
高 Temperament：
- SocialChase 权重更高；
- PassBy / 近距离 PositionNegotiation 更积极；
- 接受更高速度的社会动作；
- 仍然不能把同类互动变成攻击。

低 Temperament：
- CompanionDrift 权重更高；
- GroupDrift 权重更高；
- RoostInvitation / ChainSocialization 权重更高；
- 互动速度更平稳。


8.2 Nerve
----------
高 Nerve：
- 接受更近的社会距离；
- SocialChase 更大胆；
- PassBy 可以更贴近；

低 Nerve：
- Separation 距离更大；
- 更偏 GroupDrift / CompanionDrift / Roost；
- 避免高速近身交叉。


8.3 Conformity
---------------
高 Conformity：
- CompanionDrift 权重明显提高；
- GroupDrift 权重提高；
- RoostInvitation 响应提高；
- 更愿意加入已有微群；

低 Conformity：
- 更长 Solo Flight；
- 更偏 PassBy；
- 更少主动追随群体中心。


8.4 RoostAffinity
------------------
高 RoostAffinity：
- 更容易响应 RoostInvitation；
- 更愿意加入已有 Chain；
- SocialDrive 高时更可能结束飞行去休息；

低 RoostAffinity：
- 更偏持续 Flight / Companion / Chase。


8.5 SocialBond
---------------
SocialBond 只作为弱 partner preference：
- 高 Bond 更容易选择对方作为 Companion；
- 更容易一起响应 Roost；
- 更容易在 GroupDrift 中保持邻近；
- 可略延长 CompanionDrift；

但禁止：
- Bond 强制配对；
- Bond 让个体穿越危险；
- Bond 取消 Travel / Injury / Escape；
- Bond partner 不在视野/合理范围却发生“远程同步”；
- Bond 形成不可拆散的永久小队。

Sex 不承担 Task 10 的固定社会职责，不创建“雄性负责追逐/雌性负责休息”等硬编码。


============================================================
9. Interaction A — Companion Drift / 结伴漂飞
============================================================

这是 Task 10 最重要的基础互动之一。

目标：
两只关系合适的 Desert Batfly 在 2~6 秒内形成松散同行，而不是各自随机上下飞。

临时关系：
- TemporaryAnchor：继续执行普通中性飞行目标；
- Companion：参考 Anchor 的位置、速度和方向保持侧后方位置；

TemporaryAnchor 不是永久 Leader。
互动结束后立即失去 Anchor 身份。

Companion 的目标不能是 Anchor 身体中心，否则会导致追尾/叠加。

建议目标：
Anchor.pos
+ Anchor.velocity.normalized * backwardOffset
+ perpendicular * lateralOffset
+ small bounded verticalOffset

设计重点：
- 横向偏移明显大于垂直偏移；
- 两只看起来“同行”，不是上下叠在一起；
- offset 可基于 EntityID 稳定决定左右侧，避免每帧随机抖动；
- Anchor 不需要为了 Companion 改变自己的整个 AI；
- Anchor 若进入高优先级行为，CompanionDrift 立即结束。

建议持续：80~240 ticks。

结束条件：
- duration 完成；
- 距离过大；
- 失去合理视觉联系；
- 任一方进入 danger / travel / injury / attack / roost；
- room change / shortcut / restraint。


============================================================
10. Interaction B — Pass-by / Greeting / 擦身互动
============================================================

目标：
两只迎面或交叉接近的 Desert Batfly 不总是叠在一起再一起向上修正，而是做一个 0.5~1.2 秒的短暂侧向擦身。

触发条件示意：
- 两只都处于中性 Flight；
- 距离进入约 45~90 px；
- 相对速度显示正在接近；
- 当前没有其他 interaction；

必须使用成对一致的左右分配算法。
例如：
- 根据两只 EntityID 的稳定排序决定 Pair A / Pair B；
- 以双方连线或平均速度为参考轴；
- A 选择左侧绕行，B 选择右侧绕行；

禁止两只都因为同一个障碍逻辑同时选择 Vector2.up。

PassBy 不产生：
- AttackSlot；
- Threatened；
- Trauma；
- 水分抽取；
- retaliation；
- permanent relationship。

完成擦身后直接回到普通 Flight / SocialCooldown。


============================================================
11. Interaction C — Social Chase / 同类短追逐
============================================================

目标：
让高 Temperament、较高 Nerve、健康的个体偶尔进行 1~3 秒的同类追逐/玩闹/轻微驱赶。

必须与“骚扰轻型异种生物”完全分离。

SocialChase：
DesertBatfly <-> DesertBatfly

Existing Harass：
DesertBatfly -> other species

SocialChase 禁止进入现有：
- Approach
- Circle
- Dive
- Attach
- RetaliationCharge
- Interfere

禁止：
- 咬；
- 抽水；
- AttackSlots；
- 伤害；
- stun；
- Trauma；
- Grief；
- Intimidation；
- 捕食关系。

临时双方：
- Chaser：追逐一个预测位置，不直接撞身体；
- Chased：可进行轻微横向/弧线规避，但不得进入 Escape/Fear。

建议持续：40~120 ticks。

结束条件：
- duration 到；
- 距离过远；
- 任一方收到高优先级事件；
- 即将撞墙/进入狭窄区域；
- Chased 进入 Roost / Travel / Injury。

同一 pair 的 SocialChase 必须有较长重复 cooldown。


============================================================
12. Interaction D — Group Drift / 微群漂移
============================================================

目标：
3~6 只健康中性 Desert Batfly 形成几秒钟松散微群，让群体更像活体 flock，而不是 N 个互不相关的随机点。

MicroFlock 不是 Colony，也不是永久队伍。
- 不存档；
- 不跨 room；
- 不跨 Cycle；
- 不影响 Task 09 Colony ownership；
- 不允许 permanent leader。

建议规模：3~6。

GroupDrift 使用简化 Boids 思路，但必须是弱影响：

A) Alignment
- 轻微参考附近成员平均飞行方向；

B) Cohesion
- 离群太远时轻微回到 group center；

C) Separation
- 太近时主动分离；
- Separation 必须明显偏向水平轴；
- 避免把群体推成上下竖列。

建议权重概念：
- Separation 最强；
- Alignment 次之；
- Cohesion 最弱；

垂直修正必须被限幅。
不要让 group center 的 Y 每帧带着所有蝠蝇同步上下摆动。

实现优先采用：
- 修改/合成一个社会 localGoal；
- 继续走现有 BatFlight / Steer；

禁止：
- 自建 PathFinder；
- 直接 teleport；
- 每帧给所有成员硬设同一个 velocity；
- 全房间全连接 Boids。

建议持续：120~320 ticks。

成员可以提前离开；群体低于 3 只时自然解散为 Companion / Solo Flight。


============================================================
13. Interaction E — Roost Invitation / 休息带动
============================================================

这是解决“所有蝠蝇长期悬空”的第二个核心机制。

当前逻辑中单只蝠蝇通过 RoostChance -> TryFindRoost -> Chain/Hang。
Task 10 要增加弱社会传播：

某只健康个体开始准备 Roost / 已找到合法 Roost / 刚进入 Chain
-> 附近中性 Desert Batfly 感知到这个行为
-> 自己的 Roost 意愿临时提高
-> 可能跟去寻找邻近合法挂点或加入现有 Fly chain。

这不是命令。

RoostInvitation 不能：
- 强制所有附近蝠蝇一起挂；
- 覆盖低 RoostAffinity；
- 覆盖 danger / travel / injury；
- 让个体穿墙；
- 让个体挂到非法 tile。

影响权重：
- SocialBond 高：响应 bonus；
- Conformity 高：响应 bonus；
- RoostAffinity 高：响应 bonus；
- Temperament 低：弱 bonus；
- 当前 SocialDrive 高：更愿意结束空中活动。

建议一次 Invitation 最多影响 2~4 个附近个体，避免 15 只同时冲向同一点。

目标分配：
- 优先复用现有 TryGetRoostSpot / ChainTile；
- 平台底面 Floor roost 必须合法；
- 已有链可通过原版 CanIHangFromThisFly 等逻辑加入；
- 若同一 anchor 周围空间拥挤，应寻找附近其他合法位置，而不是身体重叠。


============================================================
14. Interaction F — Position Negotiation / Swap / 飞行位置协商
============================================================

目标：
两只中性飞行个体过近、相对速度冲突时，不要都走同一垂直避障反应。

持续时间短：约 20~50 ticks。

基本行为：
- Pair A 向一个水平/斜水平侧偏；
- Pair B 向相反侧偏；
- 绕开后立即结束；

左右选择必须稳定、成对互补，例如基于：
- EntityID 排序；
- Pair hash；
- 当前相对方向；

禁止每帧 Random 左右翻转。

这个互动可视为 PassBy 的“近距离冲突解决版”：
- PassBy 更像主动 greeting / 交叉；
- PositionNegotiation 更像碰撞空间协商。

如果检测到墙体/窄通道，优先选择真正可行的一侧；两侧都不可行则退出社会协商，让原版/现有障碍逻辑接管。


============================================================
15. Interaction G — Chain Socialization / 倒挂群聚集
============================================================

目标：
已有 Desert Batfly Chain / Roost 的位置应该成为弱社会吸引点，使倒挂群自然形成，而不是所有个体均匀散在房间里。

规则：
- 附近已有 1~4 只 Desert Batfly 倒挂时，新的 Roost candidate 评分获得弱 bonus；
- 有 SocialBond 的链成员可再增加一点 bonus；
- 仍必须通过合法 ChainTile / CanIHangFromThisFly / 空间检查；
- 不允许无限长链；
- 不允许整个房间所有蝠蝇挂在同一个像素点；

视觉目标：

---------- platform / ceiling ----------
   |      |
   A      D
   |      |
   B      E
   |
   C

而不是：

----------
A/B/C/D/E 全部重叠

ChainSocialization 必须与当前 SocialBond.SampleChain 兼容，但不要借机重写 Task 05 的 Bond 规则。


============================================================
16. Social Interaction Scheduler / 行为选择器
============================================================

不要写成：
每帧 Random.value < X -> 随机选一个互动。

建议流程：

Neutral Eligibility
-> SocialScan 到期
-> 更新 SocialDrive
-> 获取缓存邻居
-> 生成可用 interaction candidates
-> 为每个候选算 weight
-> 应用 Personality / Bond / distance / recent repetition / room crowding
-> 选择 0 或 1 个 interaction
-> reservation
-> 执行若干 ticks
-> finish/cancel
-> cooldown

候选权重必须有明显差异：

CompanionDrift：
- Bond / Conformity / calmness / 合适距离

PassBy：
- closing velocity / 当前交叉轨迹 / 中等 Nerve

SocialChase：
- Temperament / Nerve / health

GroupDrift：
- Conformity / nearby neutral count / SocialDrive

RoostInvitation：
- nearby roosting bat / RoostAffinity / Bond / Conformity

PositionNegotiation：
- collision prediction / very close spacing

ChainSocialization：
- nearby legal chain / roost desire

PositionNegotiation 属于空间安全型微互动，可比普通 social scheduler 更即时，但仍不能抢占高优先级生存状态。


============================================================
17. 防同步 / 防“全群一起做同一件事”
============================================================

必须避免大群体在同一 tick 因同一 Random 条件同步。

方法建议：
- Social scan cadence 使用 EntityID / VisualSeed 做 phase offset；
- SocialDrive 初始值有稳定个体差异；
- Interaction duration 有稳定轻微个体差异；
- room active interaction ratio 有软上限；
- 同一时间只有部分个体能成为 initiator；
- RoostInvitation 有受邀数量 cap；
- GroupDrift microflock 最大 6；

禁止所有蝠蝇共享一个全局“现在社交”计时器。


============================================================
18. 房间级 reservation 与死锁保护
============================================================

一只 Desert Batfly 同一时刻最多参与一个 Task 10 interaction。

建议房间级 registry 保存：
- creature EntityID -> interaction token；
- pair/group token -> members；
- type；
- start tick；
- optional anchor / group center；

所有 token 都是非持久的。

必须处理：
- member 死亡；
- member 被抓；
- room change；
- abstractize；
- shortcut；
- interaction cancel；
- mod Disable；

任何成员失效时都必须释放 reservation。

禁止：
- A 跟 B，B 同时跟 C，C 又要求 A；
- recursive anchor chain；
- 一个 TemporaryAnchor 挂 10 个 Companion；
- interaction cancel 后 token 永久泄漏。

CompanionDrift 默认一对一。
GroupDrift 才允许 3~6 个成员。


============================================================
19. 移动控制原则
============================================================

Task 10 不新建移动系统。

允许：
- 生成临时 localGoal；
- 使用当前 DesertBatflyAI.Steer 的安全入口；
- 使用原版 BatFlight / SwarmFlight；
- 使用已有 VisualContact / terrain 检查；
- 使用现有 Chain / Hang；

禁止：
- 每个 social mode 自己写 tile A*；
- 直接把蝠蝇 teleport 到 partner；
- 每帧硬锁定位置；
- Companion 直接复制 Anchor velocity；
- GroupDrift 所有个体速度完全相同；

社会飞行应保留轻微独立误差，让个体仍像生物而不是编队无人机。


============================================================
20. 横向布局优先：直接针对“上下柱状飞行”
============================================================

Task 10 的社会目标必须有明确的水平布局偏置。

原因：
当前原版 BatFlight 已有自然上下拍翼。如果 Social 行为再主要用 Y 轴分离，会把问题放大成“上下柱”。

因此：
- CompanionDrift lateralOffset > verticalOffset；
- GroupDrift Separation 的 X 权重大于 Y；
- PositionNegotiation 优先左右分流；
- PassBy 优先侧向交叉；
- Group center Y 修正必须限幅/低通；
- Chase 的规避优先弧线/侧向，不要每次都向上逃；

但不能完全锁死 Y。
正常拍翼、地形避障、FakeDive、Escape、Roost 接近仍可以有显著垂直动作。


============================================================
21. 与 Roost / Platform underside 的整合
============================================================

Task 10 必须复用当前：
- fly.AI.ChainTile(tile)
- DesertBatflyPlatformRoostRuntime 对 TerrainType.Floor underside 的扩展
- TryGetRoostSpot
- Fly chain

RoostInvitation / ChainSocialization 不允许维护第二套“社会 roost 合法性”。

唯一合法性来源应尽量统一：
现有 ChainTile + Desert Batfly platform extension + 当前空间检查。

如果后续平台锚点视觉偏移调整，Task 10 应自动继承，而不是复制一份坐标算法。


============================================================
22. 与 SocialBond 的整合
============================================================

Task 10 使用 SocialBond，但不重新定义 SocialBond。

允许弱影响：
- partner candidate score；
- Companion duration；
- RoostInvitation response；
- GroupDrift proximity preference；

禁止：
- 互动完成一次就大量增加 Bond；
- 用 Task 10 创建完整 friend list；
- 修改成多对象永久 Bond 网络；

如果要让成功正向互动略微强化现有 Bond，必须：
- 使用 Task 05 当前已有 API；
- 增益远低于长期 Chain / 共同经历；
- 有节流；
- 不在 Task 10 第一阶段强制要求。

默认实现可以先只“读取 Bond 作为权重”，不修改持久 Bond。


============================================================
23. 与 Injury 的整合
============================================================

严重伤病：
- 禁止发起 SocialChase；
- 禁止加入 GroupDrift；
- 禁止 CompanionDrift；
- 优先 InjuryRecovery / Roost / Hive；

轻伤：
- 可以进行低强度 CompanionDrift / GroupDrift；
- 速度/转向继续由 DesertBatflyInjury.ApplyFlight 修正；
- 不允许 Task 10 绕过 Injury.NominalFlightSpeed / LiftControl。

PostStunShock 高时同样降低/禁止社会活动。

受伤蝠蝇可以响应 RoostInvitation，但这应被视为帮助其进入合法休息点，而不是普通玩闹。


============================================================
24. 与 Fear / Intimidation / Trauma 的整合
============================================================

只要 DesertBatflyAI.HasImmediateDanger：
- 当前 Task 10 interaction 立即取消；
- reservation 释放；
- partner 不因为对方取消就进入 SocialChase；

Trauma / Fear suppression：
- 可以降低 SocialDrive 或互动发起率；
- 不能把 Social interaction 当成“治愈 PTSD”；

RaiseLocalAlarm / BreakHangChain 等已有生存逻辑优先。

如果一只正在 GroupDrift 的蝠蝇被 Peach 攻击：
- 它立即 Escape；
- group 其他成员可通过现有 Alarm/Fear 受到影响；
- Task 10 本身不制造新的恐惧广播。


============================================================
25. 与攻击 / Retaliation 的整合
============================================================

Task 10 必须与正式攻击系统完全隔离。

SocialChase 和 PassBy 不得调用：
- AcquireSlot
- FinishRetaliation
- Attach
- DrainWater
- Threatened(partner)

正式攻击开始时：
- Task 10 interaction cancel；
- reservation release；
- SocialCooldown 可暂时冻结；

正式攻击结束进入 Escape/Cooldown 后，不允许下一帧立刻开始 SocialChase。
应等待普通 SocialCooldown / neutral stabilization。


============================================================
26. 与 Task 09 的整合
============================================================

Task 09 TravelIntent 绝对优先。

有以下 purpose 时不允许新社交：
- EmergencyRefuge
- ReturnHome
- ColonyMigration

如果 interaction 期间 Task09 创建 intent：
- 立即 cancel interaction；
- 清理 pair/group token；
- 不延迟 departure；

Bond partner 可以在 Task09 自己的弱权重中影响出发/目标，但 Task 10 不得创建“跟着朋友跨房间”的额外 travel。

MicroFlock 不跨房。


============================================================
27. 原版 Drop / Swarm / Idle 的处理边界
============================================================

Task 10 的目标是减少“长期只有 Idle/Swarm”的单调感，不是删掉原版行为。

保留：
- BatFlight 的拍翼；
- SwarmFlight 的自然群体飞行；
- Idle fallback；
- 正常高度变化；
- 原版 Drop（本任务不重写）；

Task 10 应做的是：
当个体长期处于可社交 neutral flight 时，SocialDrive 逐渐制造新的短期行为机会。

如果 fly.AI.behavior == Drop 或 movMode == Passive：
- 不启动 Task 10 interaction；
- 当前 interaction 取消或暂停后结束；

不要为了社交强行把 Drop 改成 BatFlight。


============================================================
28. 性能要求
============================================================

这是 Task 10 的硬要求。

禁止：
每帧：
for each bat
  for each other bat

建议：
- social scan 每 16~30 ticks 一次；
- 每只个体有 seed phase offset；
- 房间级缓存 neutral candidates；
- 只有需要启动新 interaction 的个体才算 partner score；
- GroupDrift 只读取自身 microflock 3~6 名成员，不扫整房；
- PositionNegotiation 可在近距离缓存邻居中判断；

如果房间有 20~30 只 Desert Batfly，Task 10 不能产生明显 GC spike 或每帧 List/Dictionary 大量分配。

优先：
- 复用 scratch list；
- room scoped cache；
- stable arrays / small lists；
- 避免 LINQ 热路径。


============================================================
29. 随机性与可复现性
============================================================

社会行为可以有随机性，但不能每帧抖动。

优先使用：
- EntityID.RandomSeed / Personality.VisualSeed；
- interaction serial；
- room/game clock 低频采样；

用于：
- scan phase；
- duration；
- left/right stable offset；
- candidate tie break；

禁止：
- 每帧 Random.value 改 lateral side；
- 每帧 Random.value 改 partner；
- Debug 模式影响 RNG 序列；

Debug 开关不能改变最终社会行为。

============================================================
36. 最终设计判断
============================================================

Task 10 的最终目标不是让 Desert Batfly 变成高度组织化的社会动物，而是让它们拥有“松散、短暂、个体化”的群体生活。

正确感觉应该是：
- 它们会注意彼此；
- 会短暂同行；
- 会玩闹/驱赶；
- 会让路；
- 会形成小群；
- 会互相带动休息；
- 会自然聚集成倒挂群；
- 但每只仍然有自己的 Personality 和行动节奏。
