# Lance Scavenger — Codex 实现任务书

> 本文件是 Lance Scavenger 当前阶段的**最高优先级实现规格**。
>
> 如果本文件与旧版 `DESIGN.md`、历史讨论或临时实验代码存在冲突，以本文件为准。
>
> 目标不是做一个“拿长枪的 Elite Scavenger”，而是做一个拥有独立战斗逻辑、独立视觉语言和明确弱点的冲锋型拾荒者兵种。

---

## 1. 项目位置与职责边界

### 生物

Lance Scavenger 的代码必须放在：

```text
src/Creatures/LanceScavenger/
```

允许在该目录内按职责继续拆分，例如：

```text
LanceScavenger/
├─ Core/
├─ AI/
├─ Graphics/
├─ Combat/
├─ Integration/
└─ Debug/
```

实际结构可根据项目现状调整，但必须保持内聚、低耦合，禁止把本生物的大量逻辑塞进全局 Hook 文件。

### 专属长枪

专属武器 Scavenger Lance 的代码位于：

```text
src/Items/ScavengerLance/
```

Lance Scavenger 与 Scavenger Lance 可以互相集成，但二者必须保持清晰边界：

- 生物负责 AI、冲锋决策、持枪姿态、行为状态和兵种逻辑。
- 长枪负责自身对象注册、持久化、碰撞、枪尖/枪杆区分、物理和独立世界物品行为。
- 禁止把长枪做成 Lance Scavenger 身上的不可分离“假 Sprite”。
- 长枪即使脱手，也应作为独立世界物品继续存在。

实现长枪时同时遵守 `src/Items/AGENTS.md`，最终需要 DevConsole 生成支持。

---

# 2. 兵种定位

Lance Scavenger 是拾荒者体系中的**专业冲锋兵**。

核心不是数值更高，而是战斗方式高度偏科：

**观察目标 → 判断是否值得交战 → 寻找水平冲锋空间 → 拉开距离 → 架枪预警 → 低弧高速跃冲 → 枪尖贯刺 → 惯性反馈 → 恢复姿态 → 再次决策。**

必须做到：

- 仍然明显属于 Rain World 的 Scavenger。
- 不能退化成 Elite Scavenger 换长枪。
- 在长水平空间中威胁很高。
- 在贴脸、狭窄、复杂垂直地形中优势明显下降。
- 失去专属长枪后威胁显著降低。
- 战斗强度来自“空间 + 速度 + 枪尖方向”，而不是简单高伤害、高血量、高攻击欲。

---

# 3. 性格与攻击倾向

Lance Scavenger 的暴躁程度应处于：

```text
普通 Scavenger < Lance Scavenger < Elite Scavenger
```

但这个“更暴躁”主要表现为：

- 更警觉。
- 更敢正面对抗。
- 进入战斗状态更快。
- 面对明确敌意时更愿意主动建立攻击条件。

**不得**把它做成 Elite Scavenger 那种过强的持续追杀和暴力倾向。

具体要求：

- 对中立玩家保持拾荒者应有的社会性，不因靠近就直接发动冲锋。
- 轻度威胁时优先警告、架枪、驱赶、观察，而不是立刻攻击。
- 确认敌意后才进入完整冲锋战斗逻辑。
- 目标远离、脱离冲突或不再构成威胁后，应比 Elite Scavenger 更容易结束追击。
- 不应无意义地频繁攻击小型生物。
- 对已经失去战斗能力的目标，攻击欲应明显下降。
- 保留拾荒者群体社会行为和友军关系，不允许为了冲锋机制把它做成不顾一切的狂战单位。

AI 参数不要简单复制 Elite Scavenger 的 aggression / bravery / attack tendency 后略微改数值。应围绕本兵种行为目标重新组织决策。

---

# 4. 核心移动与战斗：跃冲

Lance Scavenger 的代表性动作是**低弧水平跃冲**。

它与 Elite Scavenger 的大跳必须有明确区别：

- 主要获得水平速度。
- 垂直速度只服务于动作自然、跨越轻微地形和避免贴地卡死。
- 不应成为普通赶路时高频使用的超级移动能力。
- 完整威力必须依赖架枪、有效冲锋距离和前方空间。
- 贴脸时不能原地瞬间发动满威力冲锋。

需要建立“冲锋通道 / Charge Lane”概念。

AI 至少应考虑：

- 前方是否有足够水平空间。
- 枪尖到目标的实际命中路径。
- 地形是否会导致立刻撞墙。
- 友军是否挡在主要冲锋路径上。
- 目标运动方向与预测位置。
- 当前是否需要先拉距。
- 当前姿态是否允许稳定架枪。

不要把它写成单一距离阈值：`距离足够 -> Jump`。

---

# 5. 近距离与失败状态

Lance Scavenger 必须有弱点，不能任何距离都强。

当目标贴脸或无法形成 Charge Lane 时，应允许：

- 短距离刺击。
- 枪杆推击或扫开目标。
- 防御性调整。
- 主动重新拉开距离。

这些都只是维持空间的手段，不应获得完整冲锋级伤害。

冲锋失败必须有真实代价：

- 落空后需要恢复。
- 高速撞墙后应明显失衡、减速或遭受反作用力。
- 不允许撞墙后立即原地转身再次满速冲锋。
- 是否脱手、踉跄、翻滚以及强度由实现者根据 Rain World 原版物理风格决定。

---

# 6. Scavenger Lance 的战斗关系

Scavenger Lance 的详细设计参考：

```text
src/Items/ScavengerLance/DESIGN.md
```

核心原则必须保留：

- 它不是普通 Spear 的简单拉长版。
- 主要伤害来自枪尖，而不是整根枪的任意碰撞。
- 高速正向枪尖命中才产生完整冲锋效果。
- 低速触碰、枪杆侧碰、尾端碰撞不能等同贯刺。
- Lance Scavenger 默认不应该把专属长枪当普通投矛高频扔掉。
- 枪身可有轻微挠曲和冲击反馈，但不能软得像绳子。
- 物品本身必须能独立掉落、抓取、保存和重新进入房间。

完整冲锋的效果应至少考虑：

- 持枪者速度。
- 枪尖朝向。
- 枪尖与目标相对方向。
- 目标体型/质量。
- 是否为真正的冲锋状态。

不要只使用一个固定 Damage 常数解决全部情况。

---

# 7. 外观总原则

整体仍以原版 Scavenger 为主体。

**不要明显修改基础体型。**

不需要刻意做成长腿型、重装型或大型个体。兵种识别依靠：

1. 完整专属面具。
2. 面具自身的前突长角。
3. 超长专属 Lance。
4. 赭黄 / 暗金土黄身份色。
5. 单侧肩部装备。
6. 胸前斜向绑带。
7. 少量动态战带。
8. 战斗姿态。

禁止做成欧洲中世纪骑士、制式军人或完整重甲单位。

仍然要有 Rain World 拾荒者的：

- 拼装感。
- 不对称。
- 临时修补感。
- 骨、旧金属、布、绳等混合材质。

# 8. 专属完整面具

Lance Scavenger 使用**完整面具**，不是半面具。

面具是第一视觉识别点。

## 8.1 面具长角

长角是**面具本体的一部分**，不是生物 Eartlers，也不是额外挂件。

它应从面具脸部/额部结构向面部前方突出，形成强烈的前向轮廓。

必须正确处理九方向透视：

- 正面看时，因为长角正朝观察者，视觉长度应明显缩短。
- 三分之四视角逐渐显露长度。
- 接近侧面时达到最明显的视觉长度。
- 不能画成“从头顶竖起来的一根角”。

面具可以有少量其他短骨突、边缘角状结构，但这些只是面具细节，视觉等级必须远低于主长角。

## 8.2 原生 Eartlers

拾荒者本身的 Eartlers 可以保留，不需要彻底删除。

但不要生成过度夸张、会与面具主长角争夺轮廓的结构。保持普通或中等程度个体差异即可。

# 10. 配色与身体装备

赭黄 / 暗金土黄是身份色，但必须克制。

建议视觉比例：

- 大部分仍为拾荒者自身自然体色。
- 骨白、灰褐、暗褐、旧金属色承担装备主体。
- 赭黄只作为身份标记和动态识别色。

## 固定识别结构

所有 Lance Scavenger 建议保留：

- 完整长角面具。
- 单侧低矮护肩。
- 一条明显的斜跨胸带。
- 少量前臂/脚踝绑带。
- 1~2 条短战带。

## 肩部

单侧护肩即可，不做双肩重甲。

材质可表现为：

- 骨板。
- 弯曲旧金属片。
- 多块硬片绑在一起。
- 拾荒来的机械外壳。

要有捆绑和修补感，避免正规盔甲。

## 胸带

胸前斜带是重要身体识别特征。

建议使用赭黄/暗金土黄布料，并保留深褐固定段、磨损和不规则边缘。

## 战带

只做短战带，不做披风。

平时存在感较低，高速冲锋时可增强速度感。

## 不建议添加

- 大披风。
- 完整胸甲。
- 双肩重甲。
- 大面积腿甲。
- 规则军服。
- 大量金黄色金属。
- 过多珠串和仪式挂件。

# 11. 动画与视觉表现：只规定预期，不锁实现

这一部分**不要过度设计逐帧动作**。

只需达到以下表现目标：

- 非战斗时仍然像自然的 Scavenger，不要始终摆架枪姿势。
- 警戒时能看出逐渐关注目标并进入准备状态。
- 完整冲锋前必须有可读预警，让玩家能从身体和长枪姿态判断“即将冲锋”。
- 跃冲应表现出低弧、高水平速度和明显前向惯性，而不是 Elite 大跳换皮。
- 命中后要有重量、冲击和惯性反馈，不能碰到目标瞬间机械停住。
- 落空、撞墙和冲锋结束后要有合理收势/恢复。
- 长枪、面具、战带在高速运动中应自然强化速度与冲击感。

**不规定**：

- 具体帧数。
- 每个 BodyChunk 的逐帧轨迹。
- 固定插值公式。
- 固定动画曲线。
- 每个肢体必须摆到某个角度。

实现者应结合 Rain World 原版程序动画、ScavengerGraphics 和物理系统自行发挥，目标是自然、有惯性、有预警、有收势。

---

# 12. AI 实现原则

不要堆一堆互相抢控制权的 Hook。

建议将兵种特有决策组织为清晰状态或模块，例如：

```text
Observe
Threaten
CreateDistance
AcquireChargeLane
Brace
Charge
Recover
CloseDefense
Disarmed
```

名称不强制，但职责必须清楚。

重要原则：

- AI 决定“现在想做什么”。
- 移动/战斗模块决定“如何执行”。
- 图形系统只负责表现，不反向承载核心 AI 判定。
- 武器对象负责自身碰撞和物理，不让生物 AI 直接硬编码每次命中结果。
- 避免状态之间每帧互相覆盖速度、姿态或目标。

特别注意友军：

- Lance Scavenger 应比普通拾荒者更认真考虑冲锋路径中的友军。
- 不要求绝对禁止误伤；Rain World 的混乱感可以保留。
- 但不能明知多个友军挡在枪尖正前方仍高频启动完整冲锋。

---

# 13. 注册、世界生成与兼容

Lance Scavenger 最终必须是可独立注册、生成、保存和加载的生物类型。

实现时检查项目现有 Creature 注册体系，不要另外造一套平行框架。

至少保证：

- CreatureTemplate 正确。
- AbstractCreature / realized creature 生命周期正确。
- AI 正确创建。
- Graphics 正确创建。
- Shortcut / room transition / den 行为不因长枪和特殊状态损坏。
- 保存与重新加载不会丢失专属类型。
- 死亡、昏迷、抓取、被其他生物攻击等原版通用状态仍正常。
- DevConsole 可以方便生成用于测试。

如果长枪需要跟随出生：

- 必须明确生成所有权。
- 避免房间重新 realize 时重复生成多把。
- 长枪脱手后不能因为生物状态更新被瞬移回手中。

---

# 14. 数值原则

第一版不要追求一次性调到最终平衡。

优先保证：

1. 行为逻辑正确。
2. 冲锋空间判断正确。
3. 动作自然。
4. 枪尖碰撞正确。
5. 失败状态真实。
6. 不破坏普通拾荒者和 Elite Scavenger。

再逐步调整：

- 冲锋速度。
- 蓄势时间。
- 恢复时间。
- 伤害。
- 推力。
- 距离阈值。
- 攻击欲。

禁止用极高伤害掩盖 AI 和物理尚未完成的问题。

---

# 15. 明确禁止项

实现中不要出现：

- 直接复制 Elite Scavenger，再替换武器。
- 持续高暴力追杀倾向。
- 没有预警的瞬发冲锋。
- 原地零距离满威力冲锋。
- 整根长枪都是高伤害判定。
- 高频连续无恢复冲锋。
- 撞墙后立刻恢复满速。
- 长枪穿墙完全无反馈。
- 为了实现简单而把长枪焊死在 Graphics 上。
- 为了视觉辨识度大幅修改拾荒者基础体型。
- 将赭黄色铺满整个身体。
- 正规骑士式重甲、披风、制式制服。
- 擅自替换或改名现有 `LanceScavengerMask` 资源。

# 16. 建议开发顺序

按以下阶段推进，尽量保证每阶段都可以单独测试：

### 阶段 A：基础注册

- 注册 Lance Scavenger。
- 能通过 DevConsole 稳定生成。
- 先复用原版 Scavenger 基础身体和 AI，确保生命周期稳定。

### 阶段 B：专属面具

- 加载现有 `LanceScavengerMask` atlas。
- 接入 0~8 方向 Sprite。
- 确认镜像、锚点、Palette、遮挡关系正常。

### 阶段 C：Scavenger Lance

- 完成独立物品注册、生成、持久化。
- 完成长度、抓持、枪尖与枪杆基础碰撞。
- DevConsole 可生成。

### 阶段 D：持枪与近战基础

- Lance Scavenger 能稳定获取并持有专属长枪。
- 普通移动、转身、攀爬、进入 shortcut 时不崩坏。
- 实现基础近距离自保和拉距逻辑。

### 阶段 E：Charge Lane 与跃冲

- 加入空间判断、拉距、架枪、冲锋、恢复状态。
- 先保证稳定和可读性，再提高智能程度。

### 阶段 F：命中物理

- 枪尖正向命中。
- 不同质量目标反馈。
- 撞墙、落空和反作用力。
- 解决穿墙、连续多次伤害等问题。

### 阶段 G：身体装备与表现

- 单侧护肩。
- 胸前斜带。
- 短战带。
- 赭黄身份色。
- 动画细化由实现者依据本任务书的“表现目标”自行发挥。

### 阶段 H：AI 与平衡打磨

- 将暴躁程度控制在普通与 Elite 之间。
- 测试群体战斗、友军、狭窄地形、垂直地形、失枪状态。
- 调整数值，但不得破坏兵种弱点。

# 17. 验收标准

第一版可视为完成时，至少满足：

- 可以稳定生成 Lance Scavenger。
- 一眼能看出其完整长角面具和专属长枪。
- 面具正确使用已有 0~8 Sprite，而非临时程序图形替代。
- 普通状态仍像 Scavenger。
- 对中立目标不会表现得像 Elite 一样过度暴力。
- 能主动拉距并寻找适合冲锋的水平空间。
- 完整冲锋有明显预警。
- 跃冲是低弧前冲，不是普通大跳。
- 枪尖命中与枪杆碰撞有明确区别。
- 命中、落空、撞墙均有可读反馈。
- 狭窄空间和失枪时明显变弱。
- 群体环境中不会因为冲锋机制频繁无脑撞友军。
- 不影响普通 Scavenger 与 Elite Scavenger 原有行为。
- 代码结构可继续扩展，而不是单文件大量特殊判断。

# 18. 给 Codex 的最终执行原则

在开始大量写代码前，先阅读项目现有 Scavenger、Creature、Item 注册方式以及相关 AGENTS 规范。

可以参考原版 Elite Scavenger、`VultureMaskGraphics`、Scavenger AI 和现有高质量生物实现，但**参考的是架构、生命周期、程序动画和兼容方式，不是直接照搬行为**。

当本任务书只描述“预期表现”而没有规定公式时，应优先选择符合 Rain World 原版程序动画与物理风格的实现，而不是机械地补齐一套固定动画状态机。

开发过程中优先解决正确性、稳定性和可读性，再做复杂表现和数值打磨。
