# Items 开发规则

- 新物品只有在正常创建/实现/拾取/使用、必要持久化、完整注册/卸载生命周期和 **DevConsole 兼容**全部完成后才算完成；缺 DevConsole 即未完成。
- 每个可独立生成的自定义物品在自身目录提供 DevConsole 支持；生成名稳定，默认参数必须得到立即可测的有效实例，不依赖正常获取流程。
- 充能、耐久、等级、模式、耗尽状态、长度等关键变体只有在能明显提高测试效率时才暴露参数；解析失败应安全回退或拒绝生成，不得产生半初始化对象。
- DevConsole 必须复用正常物品的创建、实现、房间注册和持久化路径；禁止维护测试专用假物品，禁止绕过必要的 `AbstractPhysicalObject` 或实体实现流程。
- DevConsole 需要显式注册时，初始化或 `PostModsInit` 注册，重新初始化前或 `PreModsInit` 及卸载时清理；注册与重置必须幂等，未成功注册时重置也应安全；失败必须记录且不得伪装初始化成功。
- 职责边界：`Abstract...` 保存跨房间/存档状态；物品本体负责物理、绘制和行为；`...Hooks` 负责 Rain World 接线与注册；`...DevConsoleSupport` 只负责 Console 注册、参数解析和生成入口，正常生成流程不得依赖 Console。
- 提交前验证：DevConsole 可直接生成默认状态和必要关键变体；实例可执行主要交互；跨房间、保存/读取状态正确；重复初始化和卸载不会留下重复或残余注册。
