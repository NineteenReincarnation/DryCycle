# DevTool Phase 4 — 大数据 UI 虚拟化 / 可见区计算

本阶段只处理超大数据集下的 UI 渲染成本与可见区计算，不进入第三方兼容层和最终架构合并。

## 目标

- 将固定行高的大列表从“全量逐帧绘制”改为“只绘制可见区 + overscan”。
- 把可见范围计算收敛为与 ImGui 解耦的纯逻辑，统一处理滚动位置、视口高度、行高、总数和边界。
- 保持过滤、选择、滚动定位、右键及现有编辑交互语义不变。
- 优先覆盖 DevTool 中真实存在的大列表热点，小列表继续允许直接绘制，避免为了虚拟化而虚拟化。

## 验收基线

- 空列表、负滚动、超范围滚动、视口缩放等边界下，可见区结果必须稳定且安全夹取。
- 1000 / 10000 级数据列表的逐帧 UI 工作量应随“可见行数”增长，而不是随“总条目数”增长。
- 虚拟化不得改变现有数据模型、Revision / Dirty System、History、Input Router 的职责边界。
- UI 层只消费可见区结果；可见区数学计算保持纯逻辑，便于单独验证和后续复用。
